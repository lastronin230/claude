# Когда субтитры не достались

## Сначала — версия

```bash
yt-dlp --version
```

`2025.x` и старше на YouTube не работают: либо `ERROR: The page needs to be reloaded`, либо предупреждение про PO Token и пустые таблицы субтитров. Это не чинится флагами — только обновлением.

Ловушка установки: свежие релизы требуют Python 3.10, поэтому `pip install yt-dlp` на Python 3.9 молча ставит последнюю совместимую — то есть мертвую. Ставь standalone-бинарником или через homebrew, а не pip на старом питоне.

Смена версии чинит большинство проблем ниже, так что проверяй ее до всего остального.

## «Субтитров нет» или «не отдались»

`--list-subs` печатает одинаковый текст в обоих случаях:

```
abc123 has no automatic captions
abc123 has no subtitles
```

Различает их **только строка выше таблицы**:

| Что видно | Что это значит |
|---|---|
| ничего, просто пустые таблицы | субтитров действительно нет |
| `WARNING: ... missing subtitles languages because a PO token was not provided` | дорожки есть, но отброшены — почти всегда старая версия |
| `ERROR: Sign in to confirm you're not a bot` | упала вся экстракция ролика, до субтитров дело не дошло |
| `HTTP Error 429` | лимит запросов, см. ниже |

Поэтому разведку запускай с `2>&1` и смотри весь вывод, а не только таблицы. Часть диагностики уходит в отладочный поток и видна лишь под `-v` — если картина непонятная, повтори с ним.

Отдельный нормальный случай: `has no subtitles` рядом с непустой таблицей машинных. Это просто означает, что автор не делал субтитры руками — работай с машинными.

## HTTP 429 на автопереводах

Самая частая живая проблема. Важно, что она **избирательная**: авторские субтитры и машинная дорожка оригинального языка (`-orig`) ей не подвержены, падают именно автопереводы на другие языки.

Отсюда главный вывод: не запрашивай переводы. `--sub-langs all` — гарантированный способ поймать 429, потому что дорожек перевода у ролика под две сотни.

Если перевод все-таки нужен, помогает любое одно из двух:

```bash
--sleep-subtitles 60                 # пауза перед каждой дорожкой
--cookies-from-browser firefox       # свежая сессия браузера
```

Комбинировать не нужно. И помни, что машинный перевод машинного распознавания — это двойная потеря качества: чаще правильнее взять оригинал и перевести его самостоятельно.

## PO Token

На субтитрах он сейчас **не требуется** — политика помечена как необязательная, а дефолтные клиенты работают без JS-рантайма. Если предупреждение про PO Token все же появилось, это признак старой версии, а не повод искать токен.

Менять клиент (`--extractor-args "youtube:player_client=..."`) не надо: дефолт рабочий, а подстановка клиента из старых советов в интернете как раз возвращает требование токена.

## `No subtitle format found matching "json3"`

```
WARNING: No subtitle format found matching "json3" for language en, using vtt.
```

Дорожка пришла не из обычного API субтитров, а из потокового манифеста — там существует только `vtt`. Это не ошибка: скрипт разбора умеет `vtt`, дубли он снимет сам. Просто текст будет чуть грязнее.

## Пустой или подозрительно короткий транскрипт

- Скрипт разбора завершается с сообщением `пустая транскрипция` — файл скачался, но распознать структуру не удалось. Посмотри первые строки файла глазами: возможно, приехал не тот формат.
- Текст втрое длиннее ожидаемого и фразы повторяются — разбор шел не через скрипт, а сырым `vtt`. Прогони файл через `scripts/transcript.py`.
- Файл на месте, но в нем одни `[Music]` — у ролика нет речи.

## Другие площадки

- **Vimeo** — отдает `The web client only works when logged-in`, нужны cookies.
- **TED** — в момент проверки падал на разборе ответа; возможно, временно.
- **Twitch** — субтитры не извлекаются в принципе, обсуждать нечего.

Анонимно и стабильно сейчас работает только YouTube. Для остальных площадок сразу предупреждай пользователя, что может потребоваться его сессия браузера.
