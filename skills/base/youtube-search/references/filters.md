# Сужение выдачи

## Фильтры YouTube — только через полный URL

Префикс `ytsearchN:` фильтры не принимает: набор параметров там зашит константой класса. Чтобы использовать фильтры самого YouTube (те, что в интерфейсе прячутся под кнопкой «Фильтры»), передавай обычный URL страницы результатов:

```bash
yt-dlp --flat-playlist -I 1:20 \
  --print "%(ie_key)s|%(id)s|%(duration)s|%(title)s" \
  "https://www.youtube.com/results?search_query=kotlin+coroutines&sp=EgQQARgC"
```

`sp` — это протобуф в base64. Google его не документирует, значения получены реверсом, поэтому ломаются без предупреждения — если выдача выглядит странно, первым делом убери `sp` и сравни.

| Дата загрузки | `sp` | | Длительность | `sp` |
|---|---|---|---|---|
| за час | `EgIIAQ` | | меньше 4 минут | `EgIYAQ` |
| сегодня | `EgIIAg` | | больше 20 минут | `EgIYAg` |
| за неделю | `EgIIAw` | | от 4 до 20 минут | `EgIYAw` |
| за месяц | `EgIIBA` | | | |
| за год | `EgIIBQ` | | | |

| Тип | `sp` | | Свойства | `sp` |
|---|---|---|---|---|
| видео | `EgIQAQ` | | с субтитрами | `EgIoAQ` |
| канал | `EgIQAg` | | 4K | `EgJwAQ` |
| плейлист | `EgIQAw` | | HD | `EgIgAQ` |
| фильм | `EgIQBA` | | HDR | `EgPIAQE` |
| | | | прямой эфир | `EgJAAQ` |

**Комбинации** кодируются одним значением, а не склейкой двух: `EgQQARgC` — это «только видео и длиннее 20 минут». Готовой формулы для сборки нет, проще подобрать в браузере: выставь фильтры на youtube.com и скопируй `sp` из адресной строки.

Padding `=` в конце можно опускать — `EgIQAg`, `EgIQAg==` и `EgIQAg%3D%3D` работают одинаково. Пиши без него, иначе придется думать про экранирование в шелле.

**Сортировка:** по просмотрам (`sp=CAM`) работает. По дате (`CAI`) и по рейтингу (`CAE`) сломаны на стороне YouTube и возвращают обычную релевантность — это та же поломка, из-за которой из yt-dlp убрали `ytsearchdate`.

**Фильтр «только видео» не спасает от каналов** — они лезут в выдачу все равно. Отсекай по `ie_key`, как в SKILL.md.

## Поиск внутри канала

Поддерживается официально, форма URL — как на сайте:

```bash
yt-dlp --flat-playlist \
  --print "%(title)s | https://youtu.be/%(id)s" \
  "https://www.youtube.com/@3blue1brown/search?query=linear algebra"
```

Работают `@handle`, `/channel/UC…`, `/c/…`, `/user/…`. Поиск внутри плейлиста (`playlist?list=…/search`) **не поддерживается** — выгружай плейлист целиком и фильтруй сам.

## `--match-filters` и его главная ловушка

Фильтр применяется, но с оговоркой, из-за которой им легко выстрелить себе в ногу: **при `--flat-playlist` любое отсутствующее поле считается проходящим фильтр**. Не «не знаю, значит нет», а «не знаю, значит да». Знак `?` в выражении этого не меняет.

| Фильтруется | Молча пропускает все |
|---|---|
| `duration`, `view_count`, `timestamp` | `upload_date`, `like_count`, `language`, `categories`, `tags` |

```bash
# Работает
--match-filters "duration>600 & view_count>10000"

# Не работает: upload_date на этой стадии не существует,
# пройдут все ролики, включая 2015 год
--match-filters "upload_date>20250101"

# Работает — по timestamp, с включенной опцией дат
--extractor-args "youtubetab:approximate_date" \
--match-filters "timestamp>1735689600"
```

Проверяй результат фильтра глазами: если после `--match-filters` количество строк не изменилось, скорее всего поле недоступно, а не «все подошли».

`--break-match-filters` обрывает обработку на первом несовпадении — полезно на отсортированной выдаче. Старый `--break-on-reject` еще работает, но числится устаревшим.

## Ограничение количества

`-I 1:20` — срез по номерам, пишется слитно с двоеточием. `-I:20` без дефиса yt-dlp примет за URL и упадет с `Unsupported url scheme: "i"`.
