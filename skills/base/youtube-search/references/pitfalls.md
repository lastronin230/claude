# Когда что-то идет не так

## Блокировка по IP

Поиск не требует ни cookies, ни авторизации, ни PO Token — это самая незащищенная часть YouTube. Но лимит запросов он считает по IP, и при превышении отдает не понятную ошибку, а `JSONDecodeError` или пустоту. Cookies в этой ситуации не помогают: флаг стоит на адресе, а не на аккаунте.

Ответ 429 на этом эндпоинте **не ретраится** — yt-dlp падает сразу, `--retries` не спасает.

```bash
--sleep-requests 1     # пауза между запросами метаданных, то, что нужно поиску
```

`--sleep-interval` тут бесполезен — он про паузы между скачиваниями.

Заводить аккаунт и подкладывать cookies ради поиска не надо: пользы ноль, а риск бана аккаунта реальный.

## Пустая выдача

Если пришло ноль строк и ошибки нет:

1. **Убери `sp`** — фильтр «только видео» на отдельных запросах ломается на стороне YouTube и обнуляет выдачу. Известный открытый баг.
2. **Проверь, что запрос вообще распарсился.** `ytsearch0:` и `ytsearch05:` регекс не матчит, получишь `Unsupported url scheme` вместо результата.
3. **Попробуй другой язык запроса** — по узкой русской формулировке может не быть ничего, а по английской десятки роликов.

## Пришло меньше, чем просили

Нормальная ситуация, а не ошибка. `ytsearchN` — верхняя граница; YouTube обрывает продолжение когда захочет, иногда молча. На `ytsearchall` результат плавает в разы от запроса к запросу и от версии к версии.

Если нужно гарантированное количество — запрашивай с запасом и режь на своей стороне.

## Сортировать выдачу средствами yt-dlp нельзя

Ни по дате, ни по просмотрам, ни по длительности: `--format-sort` относится к форматам внутри ролика, а не к списку. Есть только `--playlist-reverse` и `--playlist-random`.

Сортировка делается после получения выдачи — `sort`, `jq`, или на стороне того, кто показывает результат. Единственное исключение — сортировка по просмотрам через `sp=CAM`, см. `filters.md`.

## Поиск из Python

```python
from yt_dlp import YoutubeDL
from datetime import datetime, timezone

opts = {
    'extract_flat': True,
    'quiet': True,
    'no_warnings': True,
    'playlist_items': '1:20',
    'extractor_args': {'youtubetab': {'approximate_date': ['']}},
}

with YoutubeDL(opts) as ydl:
    info = ydl.extract_info('ytsearch20:kotlin coroutines', download=False)

for e in info['entries']:
    if e.get('ie_key') != 'Youtube':
        continue                      # канал, не ролик
    ts = e.get('timestamp')
    year = datetime.fromtimestamp(ts, timezone.utc).year if ts else None
    print(e['id'], e.get('duration'), e.get('view_count'), year, e['title'])
```

Три отличия от CLI, на которых легко споткнуться:

- **`extract_flat` в Python по умолчанию `False`** — без явной установки пойдет полное извлечение каждого ролика со всеми вытекающими. В CLI дефолт другой.
- **`upload_date` в Python всегда `None`**, хотя CLI его печатает: поле выводится из `timestamp` на стадии подстановки шаблона, а не кладется в структуру. Считай из `timestamp` сам.
- **`playlistend` устарел** — используй `playlist_items`.

Master требует Python 3.10 и новее.

## Версия

Экстракторы ломаются постоянно, и поиск не исключение. Команда, которая работала месяц назад и вдруг отдает пустоту или падает на разборе JSON, — первый кандидат на обновление:

```bash
yt-dlp -U                    # standalone или pip-установка
brew upgrade yt-dlp          # homebrew
```
