# Поля, вывод и язык

## Что есть в выдаче, а чего нет

При `--flat-playlist` доступна только та информация, которую YouTube кладет в саму страницу результатов:

| Есть всегда | Есть не всегда | Нет вообще |
|---|---|---|
| `id`, `url`, `webpage_url`, `title`, `duration`, `view_count`, `channel`, `uploader`, `description` (сниппет), `thumbnails`, `ie_key` | `channel_id`, `uploader_id` и их url; `live_status` и `concurrent_view_count` — только у эфиров | `upload_date`, `timestamp`, `like_count`, `language`, `subtitles`, `categories`, `tags`, `formats` |

У прямых эфиров `duration` и `view_count` пустые — вместо них `concurrent_view_count`. Если в выдаче попадаются строки без длительности, это либо эфир, либо канал.

**Не ходи за недостающими полями через `--no-flat-playlist`.** Это превращает один запрос в один запрос на каждый ролик, и ровно там начинается все, от чего поиск до сих пор был свободен: PO Token, SABR, «The page needs to be reloaded», блокировки. Двадцать роликов — двадцать шансов получить ошибку вместо выдачи. Если полное извлечение все-таки нужно, делай его точечно, для одного-двух выбранных роликов.

## Дата загрузки

Ее в выдаче нет, но можно попросить приблизительную:

```bash
yt-dlp --flat-playlist \
  --extractor-args "youtubetab:approximate_date" \
  --print "%(upload_date)s %(title)s" "ytsearch10:swiftui"
```

**Дата приблизительная в буквальном смысле**: YouTube отдает «2 года назад», yt-dlp отсчитывает это от сегодняшнего дня. Достоверен только год — день и месяц у всех роликов совпадут с сегодняшними. Сортировать по ней можно, показывать пользователю как точную дату — нельзя.

## Печать результатов

`--print` подразумевает `--simulate`, ничего не скачивается, порядок флагов неважен. `--no-simulate` нужен в обратной ситуации — когда надо и скачать, и напечатать.

```bash
# строка на ролик
--print "%(title)s | %(duration)s | %(view_count)s | https://youtu.be/%(id)s"

# весь результат одним JSON — когда нужна обработка, а не чтение
yt-dlp --flat-playlist -J "ytsearch20:запрос" | jq -r '.entries[] | "\(.duration)\t\(.title)"'
```

`--print` **не разворачивает** `\t` и `\n` — печатается литеральный текст. Нужен таб-разделитель — оберни шаблон в `$'...'`, тогда таб подставит сам шелл:

```bash
yt-dlp --flat-playlist --print $'%(title)s\t%(duration)s\t%(id)s' "ytsearch10:запрос"
```

Через `printf` это делать не надо: он попытается разобрать `%(...)` как свою директиву формата и упадет.

`-j` дает по JSON-строке на ролик, `-J` — одну структуру на всю выдачу.

## Дедупликация обязательна

Выдача содержит повторы, и yt-dlp их не убирает — на больших запросах теряется около процента. Плюс выдача нестабильна сама по себе: два одинаковых запроса подряд дают разный порядок. Всегда прогоняй результат через дедуп по `id`, особенно если объединяешь несколько запросов.

## Язык и переведенные заголовки

Поиск отдает метаданные на языке `hl`, по умолчанию английском. Из-за этого русский ролик приезжает в выдаче с англоязычным названием — YouTube показывает автоперевод, а не оригинал.

```
--flat-playlist                                  → Coroutines
--flat-playlist -X "youtube:lang=ru"             → Корутины
полное извлечение (при любом lang)               → Корутины
```

То есть автоперевод — свойство именно поисковой выдачи, оригинальный заголовок отдает только полный extract одного ролика.

```bash
yt-dlp --extractor-args "youtube:lang=ru" --flat-playlist --print "%(title)s" "ytsearch10:запрос"
```

Код языка регистрозависимый и берется из списка поддерживаемых, иначе yt-dlp упадет с ошибкой. Отдельного поля с оригинальным названием не существует. Опция местами не срабатывает — это известный открытый баг, фикс не принят, так что на нее нельзя закладываться как на гарантию.

**Определить по выдаче, на каком языке ролик, невозможно.** Поля `language` в выдаче нет (оно вообще относится к дорожке, а не к видео), фильтр по нему молча пропустит все. Единственный признак — полное извлечение и ключ вида `ru-orig` в автосубтитрах. Для практики этого слишком дорого: надежнее искать двумя запросами на двух языках и объединять, как описано в SKILL.md.

**Регион** сменить нельзя: `--geo-bypass-country` подставляет только заголовок `X-Forwarded-For` и на выдачу не влияет. Теоретически поможет прокси, но это не проверялось.
