# Поиск по YouTube через yt-dlp

yt-dlp обращается к тому же внутреннему API (InnerTube), что и сайт, и отдает выдачу структурой: id, заголовок, длительность, просмотры, канал. Это единственный дешевый способ получить список роликов программно — два HTTP-запроса на страницу, без cookies и без авторизации.

**Факты проверены на yt-dlp 2026.08.19.** YouTube ломает свои фильтры регулярно, поэтому все, что ниже помечено как ненадежное, проверяй прогоном, а не доверяй на слово.

## Рабочая база

```bash
yt-dlp --flat-playlist --sleep-requests 1 \
  --print "%(ie_key)s|%(id)s|%(duration)s|%(view_count)s|%(title)s" \
  "ytsearch20:kotlin coroutines" \
  | grep '^Youtube|' | awk -F'|' '!seen[$2]++'
```

Каждый кусок тут нужен, и убирать их наугад не стоит:

| Часть | Зачем |
|---|---|
| `--flat-playlist` | не ходить в каждое видео. Без него это +1 запрос на ролик, и именно там начинаются PO Token, SABR и «The page needs to be reloaded» |
| `--sleep-requests 1` | YouTube блокирует **по IP**, и 429 на этом эндпоинте не ретраится — ошибка приходит сразу |
| `--print` | подразумевает `--simulate`, ничего не скачается. `--no-simulate` не нужен |
| `grep '^Youtube|'` | выкидывает каналы из выдачи, см. ниже |
| `awk ... !seen[$2]++` | дубликаты в выдаче есть всегда, yt-dlp их не чистит |

## Синтаксис префикса

| Форма | Что делает |
|---|---|
| `ytsearch:запрос` | ровно **один** результат |
| `ytsearchN:запрос` | до N результатов (`ytsearch20:`) |
| `ytsearchall:запрос` | пока YouTube отдает продолжение |
| `scsearchN:` / `bilisearchN:` / `gvsearchN:` | SoundCloud, Bilibili, Google Video |

`ytsearchdate` **больше не существует** — удален в релизе 2026.02.21, потому что YouTube сломал сортировку по дате и префикс тихо возвращал обычную релевантность. Команда с ним падает с `Unsupported url scheme`. Сортировки по дате в yt-dlp сейчас нет вообще.

Двоеточие внутри запроса экранировать не надо — разделяет только первое: `"ytsearch5:c++: гайд"` ищет `c++: гайд`.

**N — это потолок, а не обещание.** Сколько придет на самом деле, предсказать нельзя: замеры на одной версии дают от сотни до пяти сотен на `ytsearchall`, и две одинаковые команды подряд возвращают разный порядок. Если пользователю нужно ровно 10 штук — бери с запасом и режь на своей стороне.

## Язык запроса выбирается по теме, а не по языку пользователя

Запрос «корутины котлин» и `kotlin coroutines` дают почти непересекающуюся выдачу, и по технике англоязычных роликов кратно больше. Спросили по-русски — это не повод искать по-русски.

```bash
# два прогона, объединить, дедуп по id
for q in "kotlin coroutines structured concurrency" "корутины kotlin structured concurrency"; do
  yt-dlp --flat-playlist --sleep-requests 1 \
    --print "%(ie_key)s|%(id)s|%(duration)s|%(view_count)s|%(title)s" "ytsearch15:$q"
done | grep '^Youtube|' | awk -F'|' '!seen[$2]++'
```

Переводи термином предметной области, а не словарем: «шторка» — это `bottom sheet`, «обводка» — `stroke`.

**Заголовки в выдаче переведены.** Поиск отдает метаданные на языке `hl`, по умолчанию английском, поэтому русский ролик приезжает с англоязычным названием — и определить по выдаче, на каком языке ролик, нельзя. Подробности и что с этим делать — `references/output.md`.

## Каналы в выдаче занимают места видео

YouTube подмешивает каналы даже в выдачу с фильтром «только видео» — это его баг, и yt-dlp его не чинит. Канал занимает один из N слотов, приезжает с `duration = None`, а при обработке разворачивается в сотни роликов.

`--match-filters` тут не поможет: все, что не одиночное видео, проходит фильтры без проверки. Отсекать надо на выходе по `%(ie_key)s` — у видео он `Youtube`, у канала `YoutubeTab`.

## Что отдавать пользователю

Результат поиска — это список, который человек будет глазами выбирать, поэтому отдавай его так, чтобы выбор можно было сделать не открывая браузер:

```
1. Kotlin Coroutines: Structured Concurrency — 42 мин, 310K просмотров
   https://youtu.be/abc123
```

- **Длительность и просмотры** — обычно этого хватает, чтобы отсеять мусор. Просмотры не показатель качества, но показатель того, что ролик вообще смотрели.
- **Не выдумывай то, чего нет в выдаче.** Даты загрузки при обычном поиске нет, языка ролика нет, оценок нет. Нужна дата — см. `references/output.md`, там она добывается отдельно и с оговорками.
- **Ссылку давай короткую** (`https://youtu.be/<id>`) — она строится из `id`, ее не надо запрашивать отдельно.
- Если пользователь искал под скачивание — просто передай найденные ссылки дальше, качать отсюда не надо.

## Когда этот скилл не нужен

- **Скачать конкретный ролик по ссылке** — это не поиск.
- **«Какой ролик лучше посмотреть»** — субъективный выбор. Веб-поиск подтянет обсуждения и рейтинги, а `ytsearch` вернет только то, что YouTube считает релевантным.
- **Метаданные одного известного ролика** — `yt-dlp -j "<URL>"` без всякого поиска.
- **Поиск внутри плейлиста** — не поддерживается: скачай список плейлиста целиком и фильтруй сам.
