# Subagents

Subagent — отдельный агент с изолированным контекстом, вызывается через Agent tool (`subagent_type: <name>`). Полезен для параллелизации, исследовательских задач, где не хочется засорять основной контекст, и для специализации.

## Расположение

- `~/.claude/agents/<name>.md` — глобальные
- `./.claude/agents/<name>.md` — проектные (коммитятся)

Имя файла (без `.md`) = `subagent_type`, которое передаётся в Agent tool.

## Формат

```markdown
---
name: code-reviewer
description: Независимое ревью кода. Используй когда нужен второй взгляд на изменения или проверка безопасности.
tools: Read, Grep, Glob, Bash(git:*)
model: claude-sonnet-4-6
---

Ты опытный код-ревьюер. Анализируй переданный код на:

1. Корректность — логические ошибки, edge cases, null/undefined
2. Безопасность — OWASP top 10, injection, утечки
3. Производительность — N+1, лишние аллокации
4. Стиль — соответствие конвенциям проекта

Формат ответа:
- `**Что:**` — краткое описание находки
- `**Где:**` `file.ts:123`
- `**Почему:**` — обоснование
- `**Как:**` — предлагаемое исправление
```

### Frontmatter-поля

| Поле | Обязательно | Описание |
|---|---|---|
| `name` | да | Уникальное имя (= имени файла) |
| `description` | да | Когда использовать — триггер для основного агента |
| `tools` | нет | Белый список инструментов; если не указано — все доступные |
| `model` | нет | Модель по умолчанию; можно override при вызове |

### tools

Те же правила, что и в `allowed-tools` у slash-команд. Примеры:

```yaml
tools: Read, Grep, Glob        # только чтение
tools: Read, Edit, Write, Bash # чтение + редактирование + shell
tools: Bash(git:*), Read       # ограниченный shell + чтение
```

Если `tools` не указан — subagent наследует все инструменты основного агента.

## Вызов

Основной агент вызывает subagent через Agent tool:

```
Agent({
  subagent_type: "code-reviewer",
  description: "Ревью PR",
  prompt: "Разбери изменения в feature/auth и выдай список находок."
})
```

В auto-mode и при `run_in_background: true` несколько subagents можно запускать параллельно в одном ответе.

## Как писать description (критично для триггера)

`description` — это то, по чему основной агент решает «а надо ли вызывать этого subagent'а». Должно быть:
- **Конкретно** — что делает, когда нужен.
- **С триггерными фразами** — «используй когда пользователь просит…».
- **Не перегружено** — 1-3 предложения.

Пример хорошего description:

```
Специализированный ресёрч-агент для быстрого поиска по кодбезу. Используй когда нужно найти файлы по паттерну, грепнуть код по ключевым словам или ответить на вопрос вроде «как работают API endpoints». Всегда указывай уровень тщательности: quick / medium / very thorough.
```

Пример плохого description:

```
Помогает с кодом.
```

## Примеры subagents

### `security-reviewer`

```markdown
---
name: security-reviewer
description: Проверяет pending-изменения на уязвимости. Используй перед мержем security-sensitive кода, перед коммитом секретов, при работе с auth/crypto/user-input.
tools: Read, Grep, Glob, Bash(git diff:*)
---

Ты security researcher. Анализируй staged diff на уязвимости из OWASP Top 10:
1. Injection (SQL, command, path traversal)
2. Broken authentication / session
3. Sensitive data exposure
4. XSS / CSRF
5. Деприкейт'нутая крипто / weak secrets

…
```

### `test-writer`

```markdown
---
name: test-writer
description: Пишет юнит-тесты для Kotlin/JS/Python кода. Используй когда пользователь просит «покрой тестами», «напиши тесты для X», или после добавления новой функции.
tools: Read, Write, Edit, Bash
---

…
```

## Subagent vs skill vs slash-команда

- **Subagent** — изолированный контекст, отдельный вызов, возвращает summary. Для параллелизации.
- **Skill** — инструкции, инжектируемые в основной агент при триггере. Для повторяющихся паттернов.
- **Slash-команда** — явный одноразовый вызов. Без изоляции контекста.

## Антипаттерны

- **Subagent без `description`.** Не будет триггериться.
- **`tools: *` по умолчанию для dangerous subagent'ов.** Ограничивай набор инструментов явно.
- **Subagent, который делает то же, что основной агент.** Тогда лучше skill.
- **Слишком общий subagent.** «helper-agent» — не описание. Специализируйся.
