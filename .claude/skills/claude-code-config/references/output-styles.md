# Output Styles

Output style — способ переопределить стиль ответов Claude Code для конкретных ситуаций (например, «учебный режим», «деловой тон», «только код без объяснений»).

## Расположение

- `~/.claude/output-styles/<name>.md` — глобальные
- `./.claude/output-styles/<name>.md` — проектные

## Формат

```markdown
---
name: teaching
description: Режим обучения — подробно объясняет, почему, до кода
---

Ты в режиме преподавателя. Перед каждым действием объясни, ЧТО ты собираешься сделать и ПОЧЕМУ. После — разбери, что получилось и какие альтернативы были. Используй структуру:

1. **Цель**
2. **Подход** (и почему именно такой)
3. **Реализация** (код)
4. **Разбор** (что важно)
5. **Альтернативы**

Говори на языке пользователя. Избегай жаргона без объяснения.
```

### Frontmatter

| Поле | Обязательно | Описание |
|---|---|---|
| `name` | да | Имя стиля |
| `description` | да | Когда и зачем использовать |

## Применение

Output style переключается командой `/output-style <name>` в рантайме или устанавливается по умолчанию в `settings.json`:

```json
{
  "outputStyle": "teaching"
}
```

Стиль применяется поверх системного промпта CC — не переопределяя core-правила, а дополняя их.

## Output style vs skill

- **Output style** — как Claude ОТВЕЧАЕТ (тон, структура, детализация). Применяется ко всем ответам.
- **Skill** — ЧТО Claude делает в конкретной ситуации (рабочий процесс, инструкции). Триггерится по контексту.

Если хочешь «всегда отвечай кратко» — это output style. Если «когда пользователь просит ревью, делай X» — это skill.

## Примеры

### `concise`

```markdown
---
name: concise
description: Лаконичные ответы без лишних слов. Для опытных пользователей.
---

Отвечай максимально кратко. Убери:
- вступления («Вот решение»)
- заключения («Надеюсь помогло»)
- дисклеймеры
- повторение того, что ясно из кода

Код должен говорить за себя. Комментарии только там, где логика нетривиальна.
```

### `explanatory`

```markdown
---
name: explanatory
description: Подробные объяснения для изучающих. Используй когда пользователь учится или работает с незнакомой технологией.
---

Перед каждым значимым изменением кода объясняй:
- что ты меняешь
- почему именно так
- какие альтернативы рассматривал
- на что обратить внимание в будущем

Ссылайся на документацию / best practices.
```

## Антипаттерны

- **Output style, пытающийся сделать то, что делает skill.** Output style не должен содержать пошаговые инструкции для конкретных задач.
- **Переопределение core-правил CC.** Output style не может отменить безопасностные правила или обязательные процедуры.
