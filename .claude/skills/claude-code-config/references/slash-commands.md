# Slash-команды

Пользовательские команды `/name`, которые запускаются явным вводом. Хранятся в `.claude/commands/<name>.md`.

## Расположение

- `~/.claude/commands/` — глобальные (видны во всех проектах).
- `./.claude/commands/` — проектные (коммитятся).

Имя файла = имя команды. `foo.md` → `/foo`. Подкаталоги создают namespace: `git/commit.md` → `/git:commit`.

## Формат

```markdown
---
description: Краткое описание команды (показывается в picker'е)
argument-hint: "[branch] [--flag]"
allowed-tools: Bash(git:*), Read, Grep
model: claude-sonnet-4-6
---

Тело промпта. Поддерживается markdown.

Аргументы доступны как `$1`, `$2`, … `$9`, либо `$ARGUMENTS` (вся строка).

Пример: сделай ревью изменений относительно ветки `$1`.
```

### Frontmatter-поля

| Поле | Обязательно | Описание |
|---|---|---|
| `description` | нет, но рекомендуется | Короткое описание для picker'а |
| `argument-hint` | нет | Подсказка формата аргументов |
| `allowed-tools` | нет | Список разрешённых инструментов (аналогично permissions) |
| `model` | нет | Форсировать модель для этой команды |
| `disable-model-invocation` | нет | `true` — команду нельзя вызвать через Skill tool |

### Аргументы

- `$1`, `$2`, … `$9` — позиционные аргументы.
- `$ARGUMENTS` — вся строка после `/name `.
- Если аргумент не передан, `$1` пустой (но подстрока сохранится).

## Примеры

### `/review` — ревью ветки

`.claude/commands/review.md`:

```markdown
---
description: Ревью изменений текущей ветки относительно base
argument-hint: "[base-branch=main]"
allowed-tools: Bash(git:*), Read, Grep, Glob
---

Сделай ревью изменений на текущей ветке относительно `${1:-main}`. Проверь:
- логические ошибки
- безопасность
- стиль кода (см. CLAUDE.md проекта)
- тесты покрывают новую логику

Формат: список находок с файлами и строками.
```

### `/fix-issue` — исправить GH issue

`.claude/commands/fix-issue.md`:

```markdown
---
description: Забрать GitHub issue и начать работу
argument-hint: "<issue-number>"
allowed-tools: Bash(gh:*), Read, Edit, Write, Grep, Glob
---

Возьми issue #$1:
1. `gh issue view $1` — прочти описание
2. Найди релевантные файлы в репозитории
3. Составь план фикса
4. Реализуй
5. Напиши коммит со ссылкой на #$1
```

### `/deploy:staging` — namespace

`.claude/commands/deploy/staging.md` → `/deploy:staging`:

```markdown
---
description: Деплой на staging
allowed-tools: Bash(kubectl:*), Bash(helm:*)
---

Задеплой текущую ветку на staging-кластер.
```

## Slash-команда vs subagent vs skill

- **Slash-команда** — пользователь явно вызывает `/name`. Одноразовое действие с понятными аргументами.
- **Subagent** — Claude вызывает через Agent tool, работает в отдельном контексте. Для параллелизации или изоляции.
- **Skill** — автоматически триггерится по описанию, когда контекст подходит. Для повторяющихся паттернов.

## Антипаттерны

- **Команда, которая всё время нужна.** Если команду вызывают каждый раз автоматически по контексту — это skill, не команда.
- **Длинный промпт с инструкциями на все случаи.** Держи команду короткой и конкретной.
- **Команда без `allowed-tools`.** Она унаследует текущие permissions — обычно нормально, но для опасных действий лучше явно ограничить.
- **Hardcoded пути.** Используй `$ARGUMENTS` или относительные пути от корня проекта.
