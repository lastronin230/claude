# Память (CLAUDE.md)

CLAUDE.md — файл памяти, автоматически подгружаемый в контекст сессии. Используется для правил стиля, глоссария проекта, конвенций, структуры кодбезы, целевой аудитории и т.д.

## Уровни

1. **User** — `~/.claude/CLAUDE.md`. Личные предпочтения во всех проектах.
2. **Project** — `<root>/CLAUDE.md`. Коммитится, общие правила команды.
3. **Вложенные** — `<any-subdir>/CLAUDE.md`. Автоматически подгружается при работе с файлами этого подкаталога. Идеально для специфичных правил для части кодбезы (например, `docs/tasks/CLAUDE.md`).
4. **Ad-hoc** — через `@path`, импорт файла.

CC загружает ВСЕ применимые CLAUDE.md от корня к текущей рабочей директории, плюс user-уровень.

## Формат

Обычный markdown. Никакого frontmatter.

```markdown
# Название проекта

Короткое описание.

## Редакция

Пишем «е» вместо «ё». Примеры: «еще», «мое».

## Архитектура

- Frontend: React + Vite
- Backend: Kotlin + Spring Boot
- БД: PostgreSQL

## Команды

- Сборка: `npm run build`
- Тесты: `npm test`
- Линтер: `npm run lint`

## Стиль кода

…
```

## Импорты `@file`

CLAUDE.md поддерживает синтаксис `@path/to/file` для подтягивания других файлов. Раскрываются при загрузке контекста.

```markdown
## Задачи

@.claude/rules/tasks.md
```

Это подставит содержимое `.claude/rules/tasks.md` в это место. Пути — относительно файла, где написан импорт, или абсолютные (`~/...`).

### Когда импортировать vs inline

- **Inline** — короткие правила (5-20 строк), которые логично держать в общем файле.
- **Import** — длинные разделы, которые хочется править отдельно, переиспользовать между проектами или версионировать независимо.

## Вложенные CLAUDE.md

Если в проекте есть `docs/tasks/` с особыми правилами, создай `docs/tasks/CLAUDE.md` — он автоматически подтянется при работе с файлами в этой папке, не засоряя корневой CLAUDE.md.

Пример — `docs/tasks/CLAUDE.md`:

```markdown
# Правило для файлов задач

Файлы в этой папке содержат только актуальный скоуп задачи. Запрещено писать roadmap, будущие планы, TODO на будущее.
```

## Что класть в CLAUDE.md

**Да:**
- Целевая аудитория проекта
- Структура кодбезы
- Команды сборки/теста/деплоя
- Стандарты кода (naming, архитектура)
- Глоссарий, термины
- Правила копирайта и редакции
- Известные подводные камни
- Ссылки на документацию

**Нет:**
- Секреты, токены
- Временные заметки
- «Автоматически когда X» — это hooks, не память
- Огромные куски кода (импортируй через `@`)
- Roadmap, TODO на будущее (в файлах задач)

## Размер

- **< 200 строк** — легко читается, быстро загружается.
- **200-500 строк** — начинай делить через импорты / вложенные CLAUDE.md.
- **> 500 строк** — точно пора делить. Контекст ценен.

## Authoritative source

Когда пользователь говорит «добавь правило», «запомни что», «впиши в память» — это CLAUDE.md.

Когда говорит «чтобы это автоматически выполнялось» — это hook, не CLAUDE.md. Модель может нарушить правило в памяти, харнесс hook'и — нет.

## Antipatterns

- **Правила в виде «ВСЕГДА делай X».** Лучше объяснить ПОЧЕМУ — модель умная, ей важнее мотив, чем приказ.
- **Повтор того, что модель и так знает.** «Используй семантические имена переменных» — банально. Уточняй только отклонения от общего знания.
- **Конфликты между уровнями.** User-CLAUDE.md сказал «пиши по-английски», project-CLAUDE.md сказал «по-русски» — приоритет у более специфичного (project). Но лучше не создавать такие конфликты.
- **Правила в CLAUDE.md для недетерминированного выполнения.** Если нужна гарантия — hook.

## Skill для памяти

- `init` — создаёт новый CLAUDE.md на основе кодбезы.
- Плагин `claude-md-management@claude-plugins-official` — управление CLAUDE.md-файлами.
