Часть I

Механика: как устроен текст

Восемь разделов. К концу будет понятно, откуда Text берет цвет и размер, что происходит со строкой, которая не влезла, и почему верстка расходится с макетом на пару пикселей.

01 Text и BasicText

В Compose два компонента текста, и разница между ними ровно в одном: знании о теме.

// material3
@Composable
fun Text(
    text: String,
    modifier: Modifier = Modifier,
    color: Color = Color.Unspecified,
    style: TextStyle = LocalTextStyle.current,     // ← стиль из темы
    …
) {
    val textColor = color.takeOrElse {
        style.color.takeOrElse { LocalContentColor.current }    // ← цвет из окружения
    }
    BasicText(text = text, style = style.merge(color = textColor), …)
}
TextBasicText
Пакетmaterial3foundation
Цвет по умолчаниюLocalContentColorчерный, если не задать
Стиль по умолчаниюLocalTextStyle из темыTextStyle.Default
autoSizeнетесть
Когда братьвсегда в приложении с темойсвоя дизайн-система, автоподгон размера

02 Откуда берется стиль

У одного Text четыре источника оформления, и они складываются в строгом порядке — от самого приоритетного к самому общему.

1. параметр напрямую        Text(text = …, color = Color.Red, fontWeight = Bold)
2. параметр style           Text(text = …, style = MaterialTheme.typography.titleMedium)
3. LocalTextStyle           то, что положил ProvideTextStyle: кнопка, элемент списка
4. тема                     MaterialTheme.typography.bodyLarge — значение по умолчанию

цвет отдельно: color → style.color → LocalContentColor

Практический вывод: отдельные параметры (fontSize, fontWeight, color) перебивают стиль, и это способ сломать типографику незаметно. Правильный порядок мышления — сначала выбрать роль из typography, и только если нужно отличие в одном свойстве, дописать его параметром.

// роль целиком
Text(text = gift.title, style = MaterialTheme.typography.titleMedium)

// роль плюс осознанное отличие
Text(
    text = gift.price,
    style = MaterialTheme.typography.titleMedium,
    color = MaterialTheme.colorScheme.primary
)

// то же, но через copy — когда отличий несколько
Text(
    text = gift.badge,
    style = MaterialTheme.typography.labelSmall.copy(letterSpacing = 0.5.sp)
)

03 AnnotatedString: разный стиль внутри одной строки

Когда в одной фразе нужен кусок другого цвета, жирный фрагмент или ссылка, строка собирается через buildAnnotatedString.

val text = buildAnnotatedString {
    append("Начислим ")
    withStyle(SpanStyle(fontWeight = FontWeight.SemiBold, color = MaterialTheme.colorScheme.primary)) {
        append("120 бонусов")
    }
    append(" после первой покупки")
}

Text(text = text, style = MaterialTheme.typography.bodyMedium)
ИнструментНа что действуетЧто задает
SpanStyleкусок текста цвет, размер, начертание, подчеркивание, фон
ParagraphStyleабзац целиком выравнивание, отступы, межстрочный интервал, направление
withLink(LinkAnnotation…)кликабельный кусок ссылка или обработчик нажатия

Ссылки внутри текста

Раньше для этого брали ClickableText с ручным поиском аннотации по смещению. Сейчас есть withLink: обработка нажатия, подсветка и доступность встроены.

val text = buildAnnotatedString {
    append("Нажимая кнопку, вы соглашаетесь с ")
    withLink(
        LinkAnnotation.Url(
            url = "https://example.com/terms",
            styles = TextLinkStyles(
                style = SpanStyle(
                    color = MaterialTheme.colorScheme.primary,
                    textDecoration = TextDecoration.Underline
                )
            )
        )
    ) {
        append("условиями")
    }
}

Text(text = text)

Второй вариант — LinkAnnotation.Clickable, когда по нажатию нужен не переход в браузер, а свое действие: открыть экран, показать шторку.

Автоподгон размера

BasicText(
    text = balance,
    style = MaterialTheme.typography.displaySmall,
    maxLines = 1,
    autoSize = TextAutoSize.StepBased(
        minFontSize = 16.sp,
        maxFontSize = 36.sp
    )
)

Компонент подбирает наибольший размер, при котором текст влезает в отведенное место. Параметр есть у BasicText; в Text из material3 его нет — поэтому для таких мест берется BasicText со стилем из темы, переданным явно.

05 Вертикальная метрика: почему не совпадает с макетом

Самая частая претензия дизайнера — «сверху лишние пиксели». Причина в том, что у шрифта есть собственные поля, а у строки — межстрочный интервал, и по умолчанию они распределяются не так, как в Figma.

┌──────────────────────────┐ ← верх блока текста
│   поле шрифта            │   includeFontPadding: с BOM 2024.01.01 отключено
├──────────────────────────┤
│   Заголовок              │   сама строка
├──────────────────────────┤
│   половина lineHeight    │   Trim решает, обрезать ли ее у первой и последней строки
└──────────────────────────┘
val AppTypography = Typography(
    titleMedium = TextStyle(
        fontSize = 16.sp,
        lineHeight = 24.sp,
        lineHeightStyle = LineHeightStyle(
            alignment = LineHeightStyle.Alignment.Center,   // строка по центру своего интервала
            trim = LineHeightStyle.Trim.Both                // лишнее у первой и последней строки убрано
        )
    )
)
НастройкаЧто делает
includeFontPadding Наследие View: добавляет поля по метрикам шрифта сверху и снизу. Сейчас по умолчанию false — именно поэтому верстка стала ближе к макетам
lineHeightвысота строки; в макетах задается всегда
LineHeightStyle.Trim обрезать ли половину интервала у первой и последней строки — работает только при выключенном includeFontPadding
LineHeightStyle.Alignmentкак разместить строку внутри ее интервала

Настраивается это один раз в Typography темы, а не на отдельных Text. Если расхождение с макетом системное — почти всегда дело здесь (кейс 2).

06 Измерение текста

Иногда нужно знать результат верстки: влез ли текст, сколько получилось строк, где заканчивается третья. Для этого есть колбэк и отдельный измеритель.

var isOverflowing by remember { mutableStateOf(false) }

Text(
    text = description,
    maxLines = 3,
    overflow = TextOverflow.Ellipsis,
    onTextLayout = { result ->
        isOverflowing = result.hasVisualOverflow        // текст не поместился целиком
    }
)

if (isOverflowing) {
    TextButton(onClick = onExpand) { Text(text = "Показать полностью") }
}
ИнструментКогда
onTextLayoutреакция на факт верстки: переполнение, число строк, позиции
TextLayoutResult hasVisualOverflow, lineCount, getLineEnd(i), size
rememberTextMeasurer измерить текст до отрисовки — например, чтобы нарисовать его в Canvas

07 Выделение и доступность

Текст в Compose по умолчанию нельзя выделить — в отличие от TextView с textIsSelectable. Разрешение дает контейнер.

SelectionContainer {
    Column {
        Text(text = "Номер заказа: ${order.number}")
        Text(text = order.address)
    }
}

// исключить кусок из выделения
SelectionContainer {
    Column {
        Text(text = order.address)
        DisableSelection {
            Text(text = "Служебная информация")
        }
    }
}
ЗадачаКак
Дать скопировать текстSelectionContainer вокруг блока
Скрыть декоративный текст от скринридера Modifier.clearAndSetSemantics { }
Прочитать вслух иначе, чем написано Modifier.semantics { contentDescription = "12 июля" } для «12.07»
Пометить заголовок для навигацииModifier.semantics { heading() }

08 Строки и локализация

Text(text = stringResource(R.string.gift_title))

Text(text = stringResource(R.string.gift_expires_at, date))          // с подстановкой

Text(                                                                 // со склонением
    text = pluralStringResource(R.plurals.services_count, count, count)
)
Чего нельзя делать со строками

Склеивать фразу из кусков: stringResource(R.string.left) + " " + count + " " + stringResource(R.string.days). В другом языке порядок слов другой, склонение зависит от числа, а переводчик видит обрывки без контекста. Вся фраза — один ресурс с плейсхолдерами, счетные фразы — plurals (кейс 4).

Часть II

Восемь кейсов

Задача, код как его пишут, что видно на экране, объяснение через разделы части I и правильный вариант.

Кейс 1. Название обрезано на полуслове

Строка списка сертификатов: название в одну строку, справа сумма.

Как пишут
Row(verticalAlignment = Alignment.CenterVertically) {
    Text(
        text = certificate.title,
        maxLines = 1,                       // overflow не задан
        modifier = Modifier.weight(1f)
    )
    Text(text = certificate.amount)
}
Что видно на экране
  • Короткие названия выглядят правильно
  • Длинное обрывается по краю без многоточия: «Сертификат на маник»
  • Непонятно, обрезано это или так и называется
Почему

Значение overflow по умолчанию — TextOverflow.Clip: обрезать без знака (раздел 04). Многоточие надо просить явно.

Как надо
Text(
    text = certificate.title,
    maxLines = 1,
    overflow = TextOverflow.Ellipsis,
    modifier = Modifier.weight(1f)
)

Если важен конец строки, а не начало — есть варианты, о которых обычно не знают:

Text(text = order.number, maxLines = 1, overflow = TextOverflow.StartEllipsis)   // …4512
Text(text = fileName, maxLines = 1, overflow = TextOverflow.MiddleEllipsis)      // отчет…2026.pdf
ПравилоmaxLines без overflow — всегда ошибка: они ставятся парой.

Кейс 2. Текст не совпадает с макетом по вертикали

Карточка: заголовок и подпись под ним, отступы по макету.

Как пишут
Column(modifier = Modifier.padding(16.dp)) {
    Text(text = title, fontSize = 16.sp, fontWeight = FontWeight.SemiBold)
    Spacer(modifier = Modifier.height(2.dp))     // подгоняем на глаз
    Text(text = subtitle, fontSize = 13.sp)
}
Что видно на экране
  • Дизайнер накладывает макет и показывает расхождение в 3-4 пикселя сверху
  • Расстояние между заголовком и подписью не то, что в макете, хотя Spacer подобран
  • На других экранах то же расхождение, но другой величины — подгоняли отдельно
  • После смены шрифта дизайн-системы все подгонки поехали
Почему

У строки есть межстрочный интервал, и по умолчанию его половина остается сверху и снизу блока (раздел 05). Макет в Figma рисуется иначе, поэтому визуальные края не совпадают. Подгонка Spacer лечит симптом на одном экране и ломается на следующем.

Как надо
// один раз в теме
val AppTypography = Typography(
    titleMedium = TextStyle(
        fontSize = 16.sp,
        lineHeight = 22.sp,
        fontWeight = FontWeight.SemiBold,
        lineHeightStyle = LineHeightStyle(
            alignment = LineHeightStyle.Alignment.Center,
            trim = LineHeightStyle.Trim.Both        // визуальный край совпадает с макетом
        )
    ),
    bodySmall = TextStyle(fontSize = 13.sp, lineHeight = 18.sp, lineHeightStyle = …)
)

// на экране остается только роль
Column(modifier = Modifier.padding(16.dp)) {
    Text(text = title, style = MaterialTheme.typography.titleMedium)
    Text(text = subtitle, style = MaterialTheme.typography.bodySmall)
}
ПравилоСистемное расхождение с макетом лечится в Typography, а не Spacer-ами на экранах.

Кейс 3. Ссылка внутри текста

Под кнопкой регистрации: «Нажимая кнопку, вы соглашаетесь с условиями» — последнее слово открывает документ.

Как пишут
Row {
    Text(text = "Нажимая кнопку, вы соглашаетесь с ")
    Text(
        text = "условиями",
        color = MaterialTheme.colorScheme.primary,
        modifier = Modifier.clickable { onTermsClick() }
    )
}
Что видно на экране
  • На широком экране выглядит правильно
  • На узком «условиями» уезжает за границу: Row не переносит строки
  • Область нажатия ровно по буквам, попасть сложно
  • Скринридер читает две отдельные фразы и не сообщает про ссылку
Почему

Это одна фраза, а не два текста. Разбив ее на composable, теряешь перенос по словам, а нажатие приходится приделывать модификатором — со всеми его ограничениями (раздел 03).

Как надо
val text = buildAnnotatedString {
    append(stringResource(R.string.auth_terms_prefix))
    withLink(
        LinkAnnotation.Clickable(
            tag = "terms",
            styles = TextLinkStyles(
                style = SpanStyle(
                    color = MaterialTheme.colorScheme.primary,
                    textDecoration = TextDecoration.Underline
                )
            ),
            linkInteractionListener = { onTermsClick() }
        )
    ) {
        append(stringResource(R.string.auth_terms_link))
    }
}

Text(text = text, style = MaterialTheme.typography.bodySmall)

Перенос работает как у обычного текста, нажатие обрабатывает сам компонент, скринридер сообщает про ссылку. Для внешнего адреса вместо Clickable — LinkAnnotation.Url.

ПравилоКликабельный кусок внутри фразы — это AnnotatedString с withLink, а не второй Text в Row.

Кейс 4. Фраза склеена из кусков

Под сертификатом: «Осталось 3 дня».

Как пишут
Text(
    text = stringResource(R.string.left) + " " + days + " " + stringResource(R.string.days)
)
Что видит пользователь
  • На русском при трех днях — правильно
  • «Осталось 1 дня», «Осталось 5 дня»: склонения нет
  • В английской версии порядок слов ломается, в арабской — направление
  • Переводчик видит в файле обрывки «Осталось» и «дня» без контекста
Почему

Конкатенация фиксирует порядок слов и число форм русского языка (раздел 08). Ни то, ни другое не переносится в другие локали.

Как надо
Text(text = pluralStringResource(R.plurals.certificate_days_left, days, days))
<!-- values-ru/strings.xml -->
<plurals name="certificate_days_left">
    <item quantity="one">Остался %d день</item>
    <item quantity="few">Осталось %d дня</item>
    <item quantity="many">Осталось %d дней</item>
    <item quantity="other">Осталось %d дней</item>
</plurals>
ПравилоФраза — один ресурс с плейсхолдерами. Счетная фраза — plurals. Оператор + между строками ресурсов — запрещен.

Кейс 5. Кнопка «Показать еще» появляется не всегда к месту

Описание услуги: три строки, дальше кнопка раскрытия.

Как пишут
Column {
    Text(
        text = service.description,
        maxLines = if (isExpanded) Int.MAX_VALUE else 3,
        overflow = TextOverflow.Ellipsis
    )
    if (service.description.length > 120) {          // порог подобран на глаз
        TextButton(onClick = { isExpanded = !isExpanded }) {
            Text(text = if (isExpanded) "Свернуть" else "Показать еще")
        }
    }
}
Что видит пользователь
  • У короткого описания из 130 символов кнопка есть, а разворачивать нечего — текст и так влез
  • У описания из 110 символов с переносами кнопки нет, хотя текст обрезан
  • На крупном системном шрифте порог врет всегда
Почему

Число символов ничего не говорит о том, поместился ли текст: это зависит от ширины экрана, размера шрифта, переносов. Знает об этом только результат верстки (раздел 06).

Как надо
var isExpanded by rememberSaveable { mutableStateOf(false) }
var isOverflowing by remember { mutableStateOf(false) }

Column {
    Text(
        text = service.description,
        maxLines = if (isExpanded) Int.MAX_VALUE else COLLAPSED_LINES,
        overflow = TextOverflow.Ellipsis,
        onTextLayout = { result ->
            if (!isExpanded) isOverflowing = result.hasVisualOverflow   // факт, а не догадка
        }
    )
    if (isOverflowing || isExpanded) {
        TextButton(onClick = { isExpanded = !isExpanded }) {
            Text(text = if (isExpanded) "Свернуть" else "Показать еще")
        }
    }
}
ПравилоВлез текст или нет — спрашивают у TextLayoutResult, а не считают символы.

Кейс 6. Крупная сумма не помещается

Главный экран: баланс бонусов крупным шрифтом по центру.

Как пишут
Text(
    text = balance,
    fontSize = when {                              // подбираем размер руками
        balance.length > 9 -> 20.sp
        balance.length > 6 -> 28.sp
        else -> 36.sp
    },
    maxLines = 1
)
Что видит пользователь
  • На обычных суммах выглядит нормально
  • На узком экране даже 20 sp не влезает — сумма обрезана
  • С крупным системным шрифтом ломается на всех порогах
  • Размер прыгает между 28 и 36 на соседних значениях — заметно дергается
Почему

Длина строки не равна ее ширине: у цифр разная ширина, шрифт масштабируется системой, экран бывает узким. Подбор по длине — угадывание.

Как надо
BasicText(
    text = balance,
    style = MaterialTheme.typography.displaySmall.copy(
        color = MaterialTheme.colorScheme.onSurface
    ),
    maxLines = 1,
    autoSize = TextAutoSize.StepBased(minFontSize = 16.sp, maxFontSize = 36.sp)
)

Компонент сам находит наибольший размер, при котором строка влезает в отведенное место. Стиль передается явно, потому что BasicText тему не читает (раздел 01).

ПравилоПодгон размера — autoSize у BasicText, а не when по длине строки.

Кейс 7. Таймер перерисовывает весь экран

Экран оплаты: сверху обратный отсчет до истечения брони, ниже список товаров и карта.

Как пишут
@Composable
fun CheckoutScreen(viewModel: CheckoutViewModel = hiltViewModel()) {
    val state by viewModel.state.collectAsStateWithLifecycle()

    Column {
        Text(text = "Бронь истекает через ${state.secondsLeft} с")   // читаем в теле экрана
        OrderItems(items = state.items)
        DeliveryMap(point = state.point)
        PayButton(onClick = viewModel::pay)
    }
}
Что видит пользователь
  • Отсчет идет правильно
  • Раз в секунду список и карта моргают, скролл дергается
  • На слабом устройстве заметны пропуски кадров, батарея греется
Почему

Чтение состояния в теле экрана делает границей перезапуска весь экран — каждую секунду заново прогоняются и список, и карта. Механизм разобран в статье про рекомпозицию, раздел 05.

Как надо
Column {
    ExpirationTimer(secondsLeft = { state.secondsLeft })   // чтение отложено в лямбду
    OrderItems(items = state.items)
    DeliveryMap(point = state.point)
    PayButton(onClick = viewModel::pay)
}

@Composable
private fun ExpirationTimer(secondsLeft: () -> Int) {
    Text(text = "Бронь истекает через ${secondsLeft()} с")   // перезапускается только эта функция
}
ПравилоЧасто меняющийся текст выносится в свою composable, а значение передается лямбдой.

Кейс 8. Номер заказа нельзя скопировать

Экран заказа: номер, адрес пункта выдачи, код получения.

Как пишут
Column {
    Text(text = "Заказ №${order.number}")
    Text(text = order.pickupAddress)
    Text(text = "Код получения: ${order.code}")
}
Что видит пользователь
  • Нужно отправить номер заказа в поддержку
  • Долгое нажатие ничего не дает: выделить текст невозможно
  • Адрес приходится переписывать в карты руками
  • В поддержку приходят номера с опечатками
Почему

В отличие от TextView, текст в Compose не выделяется по умолчанию — разрешение дает SelectionContainer (раздел 07).

Как надо
SelectionContainer {
    Column {
        Text(text = "Заказ №${order.number}")
        Text(text = order.pickupAddress)
        Text(text = "Код получения: ${order.code}")
    }
}

Для одного ключевого значения удобнее явное действие — кнопка копирования рядом: она заметнее, чем возможность выделить текст.

val clipboard = LocalClipboardManager.current
val scope = rememberCoroutineScope()

Row(verticalAlignment = Alignment.CenterVertically) {
    Text(text = "Код получения: ${order.code}")
    IconButton(
        onClick = {
            clipboard.setText(AnnotatedString(order.code))
            scope.launch { snackbarHostState.showSnackbar("Код скопирован") }
        }
    ) {
        Icon(painter = painterResource(R.drawable.ds_copy), contentDescription = "Скопировать код")
    }
}
ПравилоВсе, что пользователь может захотеть скопировать — номер, адрес, код, реквизиты, — либо в SelectionContainer, либо с кнопкой копирования.

Чеклист ревью

  1. maxLines всегда идет в паре с overflow.
  2. Стиль берется из typography; отдельные параметры — только для осознанных отличий.
  3. Фразы собираются из ресурсов с плейсхолдерами, счетные — через plurals.
  4. Кликабельные куски — withLink внутри AnnotatedString.
  5. Факт переполнения берется из onTextLayout, а не из длины строки.
  6. Вертикальные метрики настроены в теме один раз, а не Spacer-ами.
  7. Часто меняющийся текст изолирован в своей composable.
  8. Номера, коды и адреса можно скопировать.
Итог

Text — самый частый компонент и самый недооцененный: он читает стиль из окружения, сам решает, как перенести и что обрезать, и умеет рассказать о результате верстки. Большинство ошибок — это либо значение, заданное мимо системы (размер, цвет, склеенная фраза), либо догадка вместо факта (порог по символам вместо hasVisualOverflow).
