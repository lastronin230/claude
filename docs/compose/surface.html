Часть I

Механика: что такое Surface

Восемь разделов подряд. К концу будет понятно, за что отвечает этот компонент, какие четыре слоя он рисует и почему текст внутри окрашивается сам. Кейсы во второй части ссылаются на разделы по номерам.

01 Что это такое

Surface — лист бумаги Material: прямоугольник (или другая форма) с цветом фона, обводкой, тенью и правилом, каким цветом рисовать текст и иконки внутри. Сам он ничего не компонует — раскладку делают Column, Row, Box, — но берет на себя шесть работ.

Surface
├─ фон              цвет из темы (colorScheme.surface по умолчанию)
├─ форма            shape: скругление, вырезы; по нему же обрезается содержимое
├─ обводка          border
├─ тень             shadowElevation — настоящая тень по оси Z
├─ тональный слой   tonalElevation — подмешивание оттенка в цвет фона
└─ цвет содержимого contentColor: Text и Icon внутри берут его сами

Тот же результат на Box собирается из четырех модификаторов, и цвет текста все равно приходится задавать руками:

// на Box: форма указана трижды, contentColor не существует
Box(
    modifier = Modifier
        .shadow(elevation = 6.dp, shape = RoundedCornerShape(16.dp))
        .clip(RoundedCornerShape(16.dp))
        .background(MaterialTheme.colorScheme.surfaceContainer)
        .border(1.dp, MaterialTheme.colorScheme.outlineVariant, RoundedCornerShape(16.dp))
        .padding(16.dp)
) {
    Text(text = "Заголовок", color = MaterialTheme.colorScheme.onSurface)   // цвет вручную
}
// на Surface: форма одна, цвет содержимого выводится сам
Surface(
    shape = RoundedCornerShape(16.dp),
    color = MaterialTheme.colorScheme.surfaceContainer,
    shadowElevation = 6.dp,
    border = BorderStroke(1.dp, MaterialTheme.colorScheme.outlineVariant)
) {
    Text(text = "Заголовок", modifier = Modifier.padding(16.dp))            // цвет уже правильный
}

Разница не в длине. На Box форма указана в трех местах — в shadow, clip и border; рассинхрон между ними дает тень прямоугольником под скругленной карточкой (кейс 1). Surface берет форму один раз и применяет ко всем четырем слоям.

03 Две высоты: тональная и теневая

В Material 2 высота была одна — elevation. В Material 3 их две, и они независимы.

tonalElevationshadowElevation
Что рисуетподмешивает surfaceTint в цвет фонатень под формой
Видно в светлой темеслабо: оттенок на светлом фоне почти незаметенда
Видно в темной темеда, основной способ отделить слоислабо: тень на темном не читается
Влияет на цвет фонаданет
Ловушка

Тональная высота применяется только к цвету colorScheme.surface. Задал свой color — tonalElevation перестает что-либо делать, молча (кейс 7).

04 Вложенные Surface складывают тональную высоту

Каждый Surface публикует накопленную тональную высоту через LocalAbsoluteTonalElevation, и вложенный прибавляет свою к родительской. Смысл — вложенный лист никогда не выглядит ниже того, на котором лежит.

Surface(tonalElevation = 2.dp)          абсолютная тональная высота = 2.dp
└─ Surface(tonalElevation = 3.dp)       абсолютная = 2 + 3 = 5.dp  ← цвет считается от 5.dp
   └─ Surface(tonalElevation = 0.dp)    абсолютная = 5.dp          ← цвет тот же, что у родителя

Тени так не складываются: shadowElevation у каждого свой и рисуется независимо.

05 Откуда берется цвет текста внутри

Тот самый механизм, из-за которого текст на Surface «сам» становится читаемым:

  1. Surface берет contentColor. По умолчанию это contentColorFor(color) — поиск парного слота в схеме: surface → onSurface, primary → onPrimary, errorContainer → onErrorContainer.
  2. Этот цвет он подставляет в LocalContentColor для всего содержимого.
  3. Text без параметра color и Icon без tint читают LocalContentColor и красятся в него.
// цвет из схемы: парный on-цвет находится сам
Surface(color = MaterialTheme.colorScheme.primary) {
    Text(text = "На кнопке")                        // получит onPrimary
}

// цвет не из схемы: пары нет, contentColor задается явно
Surface(color = Color(0xFF102A43), contentColor = Color.White) {
    Text(text = "На своем фоне")
}

06 Нажимаемый Surface

У Surface есть отдельные перегрузки под взаимодействие. Это не удобство, а необходимость: обычный Surface не обрезает ripple по своей форме.

ПерегрузкаКогдаЧто добавляет
Surface(onClick = …)нажимаемый блок: строка списка, плитка ripple по форме, enabled, роль кнопки для доступности
Surface(selected = …, onClick = …)выбор одного из нескольких: чип состояние «выбрано» для доступности
Surface(checked = …, onCheckedChange = …)переключатель: плитка-тумблер состояние «включено» для доступности

07 Что построено на Surface

Почти все контейнеры Material 3 — это Surface с заранее выставленными параметрами. Поэтому «сделать карточку из Surface» имеет смысл только там, где готового компонента нет.

КомпонентЧем он является
CardSurface с формой, цветом и высотами из CardDefaults
Button, OutlinedButtonнажимаемый Surface плюс Row с отступами и типографикой
TopAppBar, NavigationBarSurface с цветом и высотой своей роли
ModalBottomSheet, AlertDialogSurface с формой и тенью поверх контента
ScaffoldSurface на весь экран как фон, плюс раскладка слотов

08 Что выбрать: Box, Surface или готовый компонент

Нужны ли форма, цвет из темы, тень или автоматический цвет текста?
│
├─ НЕТ  → Box: раскладка и, если надо, background одним модификатором
│
└─ ДА   → Есть ли готовый компонент Material для этой роли?
          │
          ├─ ДА  → Card, Button, TopAppBar, ModalBottomSheet и т.п.
          │
          └─ НЕТ → Surface
                   нажимается → перегрузка с onClick / selected / checked
                   иначе      → обычный Surface, отступы на содержимом
Часть II

Восемь кейсов

Задача, код как его пишут, что видно на экране, объяснение через разделы части I и правильный вариант.

Кейс 1. Под скругленной карточкой прямоугольная тень

Карточка компании в ленте: скругление 16 dp, легкая тень.

Как пишут
@Composable
fun CompanyCard(company: Company, modifier: Modifier = Modifier) {
    Box(
        modifier = modifier
            .shadow(elevation = 6.dp)                              // форма не указана
            .clip(RoundedCornerShape(16.dp))
            .background(MaterialTheme.colorScheme.surfaceContainer)
    ) {
        Column(modifier = Modifier.padding(16.dp)) {
            Text(text = company.name, color = MaterialTheme.colorScheme.onSurface)
            Text(text = company.category, color = MaterialTheme.colorScheme.onSurfaceVariant)
        }
    }
}
Что видно на экране
  • Карточка скруглена правильно
  • По углам торчат прямоугольные «уши» тени
  • На темной теме эффект незаметен, поэтому баг доезжает до релиза
Почему

У shadow своя форма, у clip своя. Контент обрезан по скруглению, а тень нарисована по прямоугольнику — рассинхрон из раздела 01.

Как надо
@Composable
fun CompanyCard(company: Company, modifier: Modifier = Modifier) {
    Surface(
        modifier = modifier,
        shape = RoundedCornerShape(16.dp),          // одна форма на фон, тень и обрезку
        color = MaterialTheme.colorScheme.surfaceContainer,
        shadowElevation = 6.dp
    ) {
        Column(modifier = Modifier.padding(16.dp)) {
            Text(text = company.name)               // цвет придет из contentColor
            Text(
                text = company.category,
                color = MaterialTheme.colorScheme.onSurfaceVariant
            )
        }
    }
}
ПравилоФорма задается один раз. Три места для одной формы — гарантия рассинхрона при первой же правке дизайна.

Кейс 2. В темной теме текст сливается с фоном

Блок с промо-условиями на экране акции.

Как пишут
Surface(shape = RoundedCornerShape(12.dp)) {
    Column(modifier = Modifier.padding(16.dp)) {
        Text(text = "Условия акции", color = Color.Black)      // хардкод
        Text(text = promo.rules, color = Color(0xFF666666))
    }
}
Что видно на экране
  • В светлой теме все правильно
  • В темной — черный текст на темно-сером фоне, читать невозможно
  • Дизайнер приносит скриншот, разработчик «у себя не воспроизводит» — у него светлая тема
Почему

Фон Surface берется из схемы и переключается вместе с темой, а захардкоженный цвет текста — нет. При этом весь механизм contentColor из раздела 05 остался неиспользованным: убери параметр color, и текст сам стал бы onSurface.

Как надо
Surface(shape = RoundedCornerShape(12.dp)) {
    Column(modifier = Modifier.padding(16.dp)) {
        Text(text = "Условия акции")                                      // onSurface
        Text(text = promo.rules, color = MaterialTheme.colorScheme.onSurfaceVariant)
    }
}

Свой фон, которого нет в схеме, обязывает задать пару явно:

Surface(color = Color(0xFF102A43), contentColor = Color.White) { … }
ПравилоЦвет текста внутри Surface руками не задают, пока фон взят из схемы. Проверка — переключить тему в превью или в настройках устройства.

Кейс 3. Отступ есть, а внутри его нет

Плитка бонусной программы: текст должен отстоять от краев на 16 dp.

Как пишут
Surface(
    modifier = Modifier.padding(16.dp),        // отступ снаружи Surface
    shape = RoundedCornerShape(16.dp),
    color = MaterialTheme.colorScheme.surfaceContainer
) {
    Text(text = "Ваши бонусы")
}
Что видно на экране
  • Текст прижат к самым краям карточки
  • Сама карточка стала меньше и отъехала от соседей
Почему

Модификатор применяется к самому Surface, а не к его содержимому: фон и обводка рисуются внутри отступа. Порядок модификаторов работает как везде в Compose — padding перед фоном уменьшает элемент.

Как надо
Surface(
    shape = RoundedCornerShape(16.dp),
    color = MaterialTheme.colorScheme.surfaceContainer
) {
    Text(text = "Ваши бонусы", modifier = Modifier.padding(16.dp))   // отступ на содержимом
}
ПравилоВнешние отступы — на Surface, внутренние — на содержимом.

Кейс 4. Волна нажатия вылезает за скругления

Строка списка сертификатов, нажимается целиком.

Как пишут
Surface(
    shape = RoundedCornerShape(16.dp),
    modifier = Modifier.clickable { onOpen(certificate.id) }
) {
    CertificateRow(certificate = certificate)
}
Что видно на экране
  • Нажатие работает
  • Волна ripple заливает прямоугольник, углы подсвечиваются за пределами формы
  • Отключить строку через enabled нельзя — приходится городить if вокруг обработчика
  • Скринридер не сообщает, что элемент нажимаемый
Почему

Modifier.clickable навешен снаружи и про форму Surface не знает. Перегрузка с onClick (раздел 06) обрезает ripple по своей форме и заодно дает enabled и роль для доступности.

Как надо
Surface(
    onClick = { onOpen(certificate.id) },
    shape = RoundedCornerShape(16.dp),
    enabled = certificate.isActive
) {
    CertificateRow(certificate = certificate)
}
ПравилоНажимаемый Surface — всегда перегрузкой с onClick, а не модификатором.

Кейс 5. Кнопка на месте, но не нажимается

Промо-баннер: поверх контента лежит декоративный градиентный слой.

Как пишут
Box {
    Column {
        Text(text = banner.title)
        Button(onClick = { onActivate() }) { Text(text = "Активировать") }
    }
    Surface(                                    // декоративный слой поверх
        modifier = Modifier.matchParentSize(),
        color = Color.Transparent
    ) { }
}
Что видно на экране
  • Баннер выглядит как задумано
  • Кнопка «Активировать» не реагирует на нажатия вообще
  • В логах пусто, в Layout Inspector кнопка на месте — баг ищут часами
Почему

Surface перехватывает касания даже без onClick и даже прозрачный: лист бумаги не пропускает нажатия сквозь себя. Это сделано намеренно, чтобы клик не проходил через шторку на контент под ней.

Как надо
Box {
    Box(                                        // декорация — Box, а не Surface
        modifier = Modifier
            .matchParentSize()
            .background(brush = promoGradient)
    )
    Column {
        Text(text = banner.title)
        Button(onClick = { onActivate() }) { Text(text = "Активировать") }
    }
}

Декоративный слой ушел вниз по порядку и перестал быть Surface. Если слой обязан быть сверху — ему нужен Modifier.pointerInput(Unit) { } с явным пропуском событий или другая композиция.

ПравилоЭлемент не реагирует на нажатия — проверь, не лежит ли сверху Surface. Для декораций берется Box.

Кейс 6. Вложенная карточка светлее, чем задумано

Карточка заказа, внутри нее — блок доставки на том же уровне.

Как пишут
Surface(tonalElevation = 3.dp, shape = RoundedCornerShape(16.dp)) {
    Column {
        OrderHeader(order = order)
        Surface(tonalElevation = 3.dp, shape = RoundedCornerShape(12.dp)) {   // еще +3
            DeliveryBlock(delivery = order.delivery)
        }
    }
}
Что видно на экране
  • В светлой теме разница почти незаметна
  • В темной блок доставки заметно светлее карточки, хотя по макету они на одном уровне
  • Чем глубже вложенность, тем светлее: на третьем уровне фон уходит в серый
Почему

Тональные высоты складываются через LocalAbsoluteTonalElevation (раздел 04): внутренний блок считает цвет от 6 dp, а не от 3.

Как надо
Surface(tonalElevation = 3.dp, shape = RoundedCornerShape(16.dp)) {
    Column {
        OrderHeader(order = order)
        Surface(
            color = MaterialTheme.colorScheme.surfaceContainerHigh,   // слой задан цветом
            tonalElevation = 0.dp,
            shape = RoundedCornerShape(12.dp)
        ) {
            DeliveryBlock(delivery = order.delivery)
        }
    }
}
ПравилоВложенным Surface — tonalElevation = 0.dp, а слои различать слотами surfaceContainer*.

Кейс 7. tonalElevation не делает ничего

Блок с фирменным цветом фона, дизайнер просит «приподнять» его.

Как пишут
Surface(
    color = Color(0xFFEFEFEF),        // цвет не из схемы
    tonalElevation = 8.dp             // молча ничего не делает
) { … }
Что видно на экране
  • Фон точно такой же, как без tonalElevation
  • Ни ошибки, ни предупреждения — параметр просто игнорируется
Почему

Подмешивание оттенка применяется только к цвету colorScheme.surface (раздел 03). Свой цвет — свой и остается.

Как надо
// вариант 1: взять слот схемы, который и заменяет ступени тональной высоты
Surface(color = MaterialTheme.colorScheme.surfaceContainerHigh) { … }

// вариант 2: если фон фирменный — отделять тенью, а не тоном
Surface(color = Color(0xFFEFEFEF), contentColor = Color.Black, shadowElevation = 4.dp) { … }
ПравилоТональная высота работает только со слотами схемы. Свой цвет — отделяй тенью или бери готовый слот.

Кейс 8. Своя карточка вместо готового компонента

Карточка в списке — «как Card, только со своими отступами».

Как пишут
@Composable
fun MyCard(content: @Composable () -> Unit) {
    Surface(
        shape = RoundedCornerShape(12.dp),                 // свои дефолты
        color = MaterialTheme.colorScheme.surface,
        shadowElevation = 2.dp
    ) { content() }
}
Что видно на экране
  • Сначала совпадает с макетом
  • После обновления дизайн-системы радиус карточек стал 16 dp — везде, кроме этих
  • В темной теме фон отличается от соседних карточек: у Card цвет surfaceContainerLow, а тут surface
Почему

Почти все контейнеры Material 3 — это уже Surface с параметрами своей роли (раздел 07). Свой Surface означает свои дефолты, которые живут отдельно от темы и разъезжаются с ней при первом же обновлении.

Как надо
Card(
    shape = MaterialTheme.shapes.medium,
    colors = CardDefaults.cardColors(),
    elevation = CardDefaults.cardElevation(defaultElevation = 2.dp)
) { content() }

Свой Surface оправдан там, где роли в Material нет: нестандартная плитка, блок с вырезом, элемент собственной дизайн-системы.

ПравилоСначала ищется готовый компонент, и только если роли нет — Surface.

Итог

Surface отвечает на четыре вопроса за раз: какой формы блок, какого он цвета, как отделен от фона и каким цветом писать внутри. Все, что не требует ни одного из этих ответов, — Box. Все, для чего в Material 3 есть роль, — готовый компонент, который внутри и так окажется Surface.
