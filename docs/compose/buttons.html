Часть I

Механика: из чего собрана кнопка

Восемь разделов подряд. К концу будет понятно, почему кнопка — это не «прямоугольник с текстом и обработчиком», какой из пяти типов брать и что именно ломается, когда кнопку делают руками.

01 Из чего собрана

Кнопка Material 3 — это Surface с нажатием, внутри которого Row. Между ними два слоя, которые и делают содержимое «правильным» само по себе. Реализация в androidx, сокращенно:

@Composable
fun Button(
    onClick: () -> Unit,
    modifier: Modifier = Modifier,
    enabled: Boolean = true,
    shape: Shape = ButtonDefaults.shape,
    colors: ButtonColors = ButtonDefaults.buttonColors(),
    elevation: ButtonElevation? = ButtonDefaults.buttonElevation(),
    border: BorderStroke? = null,
    contentPadding: PaddingValues = ButtonDefaults.ContentPadding,
    interactionSource: MutableInteractionSource? = null,
    content: @Composable RowScope.() -> Unit
) {
    Surface(
        onClick = onClick,
        modifier = modifier.semantics { role = Role.Button },      // роль для скринридера
        enabled = enabled,
        shape = shape,
        color = colors.containerColor(enabled),                    // цвет зависит от состояния
        contentColor = colors.contentColor(enabled),               // и уходит в LocalContentColor
        shadowElevation = elevation?.shadowElevation(enabled, interactionSource)?.value ?: 0.dp,
        border = border,
        interactionSource = interactionSource
    ) {
        ProvideContentColorTextStyle(                              // типографика для содержимого
            contentColor = colors.contentColor(enabled),
            textStyle = MaterialTheme.typography.labelLarge
        ) {
            Row(
                modifier = Modifier
                    .defaultMinSize(
                        minWidth = ButtonDefaults.MinWidth,
                        minHeight = ButtonDefaults.MinHeight
                    )
                    .padding(contentPadding),
                horizontalArrangement = Arrangement.Center,
                verticalAlignment = Alignment.CenterVertically,
                content = content
            )
        }
    }
}

Разложим по слоям — дальше каждый из них разбирается отдельно:

Button
├─ Surface(onClick)          форма, цвет контейнера, ripple по форме, перехват касаний
│   └─ semantics { Role.Button }   скринридер говорит «кнопка», а не «текст»
├─ colors: ButtonColors      четыре цвета: контейнер и содержимое × включена и выключена
├─ elevation: ButtonElevation  пять высот: покой, нажатие, фокус, наведение, выключена
├─ ProvideContentColorTextStyle
│   ├─ LocalContentColor     Text и Icon внутри красятся сами
│   └─ labelLarge            размер и начертание подписи — тоже сами
└─ Row(contentPadding)       содержимое по центру, минимум 58 × 40 dp, отступы по спецификации

Тот же результат руками — это шесть разных механизмов, и четыре из них обычно забывают:

Box(
    modifier = Modifier
        .clip(RoundedCornerShape(20.dp))
        .background(MaterialTheme.colorScheme.primary)
        .clickable { onPay() }                      // ripple прямоугольный, enabled нет,
        .padding(horizontal = 24.dp, vertical = 10.dp)   // область нажатия = размеру
) {
    Text(                                           // цвет и стиль — руками, в каждой кнопке заново
        text = "Оплатить",
        color = MaterialTheme.colorScheme.onPrimary,
        style = MaterialTheme.typography.labelLarge
    )
}
Button(onClick = onPay) {
    Text(text = "Оплатить")
}

02 Пять типов и иерархия

Тип кнопки — это не оформление, а вес действия на экране. Material задает иерархию: одно главное действие, остальное тише.

вес      компонент              как выглядит
высокий  Button                 ██████████   заливка цветом primary
         FilledTonalButton      ▓▓▓▓▓▓▓▓▓▓   заливка приглушенным secondaryContainer
         ElevatedButton         ░░░░░░░░░░   светлая заливка + тень
         OutlinedButton         └────────┘   только рамка
низкий   TextButton              Текст       только подпись

Технически все пять — одна и та же функция с разными наборами по умолчанию:

ТипcontainerColorelevationborder

FilledTonalButtonsecondaryContainer0 dpнет
ElevatedButtonsurfaceContainerLow1 dp, растет при нажатиинет

Отсюда практический вывод: выбор типа — это выбор роли, а не картинки. Если в макете две одинаково залитых кнопки рядом, вопрос не в цвете, а в том, какое действие главное — второе должно стать тональным или контурным.

ТипГде применяется
Button«Оплатить», «Записаться», «Подтвердить» — одна на экран

TextButtonв диалогах, под текстом, в списках: «Подробнее», «Изменить»

03 ButtonDefaults: наборы, а не значения

Главное недоразумение вокруг ButtonDefaults — считать его набором дефолтных значений, которые можно заменить своими. На самом деле каждый его объект хранит все состояния сразу и сам переключает их.

ButtonColors — четыре цвета

ButtonDefaults.buttonColors(
    containerColor = MaterialTheme.colorScheme.primary,
    contentColor = MaterialTheme.colorScheme.onPrimary,
    disabledContainerColor = MaterialTheme.colorScheme.onSurface.copy(alpha = 0.12f),
    disabledContentColor = MaterialTheme.colorScheme.onSurface.copy(alpha = 0.38f)
)

Внутри кнопки это превращается в одну строку colors.containerColor(enabled). Значит условие в коде вызывающего — дубль логики, которая уже есть, и обычно худший (кейс 4):

containerColor = if (enabled) Color(0xFF6750A4) else Color(0xFFE0E0E0)

Переопределить можно только часть: остальные поля останутся дефолтными и корректными в обеих темах. Если набор уже получен откуда-то, у него есть copy:

// только цвет контейнера, disabled-цвета не трогаем
colors = ButtonDefaults.buttonColors(
    containerColor = MaterialTheme.colorScheme.tertiary,
    contentColor = MaterialTheme.colorScheme.onTertiary
)

// точечная правка готового набора
colors = ButtonDefaults.textButtonColors().copy(contentColor = MaterialTheme.colorScheme.error)

ButtonElevation — пять высот

ButtonDefaults.buttonElevation(
    defaultElevation = 0.dp,      // покой
    pressedElevation = 0.dp,      // нажата
    focusedElevation = 0.dp,      // фокус с клавиатуры или пульта
    hoveredElevation = 1.dp,      // наведение курсором или стилусом
    disabledElevation = 0.dp      // выключена
)

Кнопка сама подписывается на interactionSource и анимирует переход между этими значениями. Поэтому «убрать тень» — это elevation = null, а не shadowElevation = 0.dp где-то снаружи: снаружи пропадет и анимация состояний.

Размеры и отступы

04 Слот содержимого: это Row

У кнопки нет параметра text. Вместо него слот — лямбда с ресивером RowScope. Это дает три вещи сразу: внутрь можно положить что угодно, доступны Modifier.weight и align, а элементы автоматически становятся в строку по центру.

Button(onClick = onShare, contentPadding = ButtonDefaults.ButtonWithIconContentPadding) {
    Icon(
        painter = painterResource(R.drawable.ds_share),
        contentDescription = null,                       // текст рядом уже все говорит
        modifier = Modifier.size(ButtonDefaults.IconSize)
    )
    Spacer(modifier = Modifier.size(ButtonDefaults.IconSpacing))
    Text(text = "Поделиться")
}

Содержимое получает от кнопки две вещи, о которых легко забыть:

Что приходитОткудаЧто это значит на практике
LocalContentColorcolors.contentColor(enabled) Text без color и Icon без tint красятся правильно, в том числе в выключенном состоянии
labelLargeProvideContentColorTextStyle подпись уже нужного размера и начертания, style задавать не надо
Button(onClick = onPay, enabled = false) {
    Text(
        text = "Оплатить",
        color = MaterialTheme.colorScheme.onPrimary,   // выключенная кнопка останется с ярким текстом
        style = MaterialTheme.typography.bodyMedium    // и с чужой типографикой
    )
}

05 Состояния и взаимодействие

У кнопки пять состояний. Четыре из них рантайм отслеживает сам через interactionSource, пятое задаешь ты параметром.

СостояниеОткуда беретсяЧто меняется
покой—базовые цвета и высота
нажатаPressInteractionripple, pressedElevation
фокусFocusInteractionfocusedElevation, обводка фокуса
наведениеHoverInteractionhoveredElevation — мышь, стилус, ChromeOS
выключенаenabled = false disabled-цвета, снятие обработчика и ripple, сообщение скринридеру

enabled — это не только «серый цвет»: кнопка перестает принимать касания, перестает показывать волну и сообщает о недоступности. Поэтому условие живет в одном месте:

Button(
    onClick = { viewModel.pay() },
    enabled = state.isPayEnabled && !state.isPaying      // одна точка правды
) {
    Text(text = "Оплатить")
}

Если на нажатие должно реагировать что-то за пределами кнопки — подсветиться соседнему блоку, измениться подписи, — берется interactionSource, а не своя обработка касаний:

val interactionSource = remember { MutableInteractionSource() }
val isPressed by interactionSource.collectIsPressedAsState()

Button(onClick = onPay, interactionSource = interactionSource) {
    Text(text = if (isPressed) "Секунду…" else "Оплатить")
}
Чего не делать

Modifier.clickable поверх кнопки — обработчик сработает дважды и появится второй слой ripple. Если нужно перехватить нажатие раньше кнопки, это pointerInput с осознанным потреблением события, а не второй clickable.

06 Размер и доступность

Визуальный размер и область нажатия — разные вещи. Кнопка может быть высотой 40 dp, но нажиматься в области 48 dp: вокруг нее есть невидимый запас, который добавляет Modifier.minimumInteractiveComponentSize().

┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐   48 dp — область нажатия, невидима
│  ┌───────────────────┐  │
│  │    Оплатить       │  │   40 dp — то, что видно: MinHeight
│  └───────────────────┘  │
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘

у IconButton то же самое: иконка 24 dp, область нажатия 48 dp

Отсюда две вещи. Первая: кнопки в ряду не стоит ставить ближе 8 dp друг к другу — их невидимые области нажатия начнут пересекаться. Вторая: если кнопка выглядит меньше 48 dp и при этом плохо нажимается, значит она собрана руками и запаса у нее нет (кейс 3).

Что нужно доступностиКто дает
роль «кнопка» для скринридераsemantics { role = Role.Button } внутри компонента
сообщение «недоступно»enabled = false
описание действия для кнопки без текстаcontentDescription у иконки — обязателен
область нажатия 48 dpminimumInteractiveComponentSize внутри компонента
работа с клавиатуры и пультафокус и Enter — тоже из коробки
Единственное, что нельзя опускать

У кнопки без текста contentDescription — единственное, что услышит незрячий пользователь. null ставится только там, где рядом есть подпись, объясняющая действие: в Button с иконкой и текстом — да, у IconButton — никогда.

08 Дерево решений

Что делает элемент?
│
├─ главное действие экрана
│    ├─ в потоке контента          → Button
│    └─ плавает над контентом      → FloatingActionButton (в слот Scaffold)
│
├─ второе по важности рядом с главным  → FilledTonalButton
│     └─ фон пестрый, нужна отбивка    → ElevatedButton
│
├─ второстепенное, обратимое (отмена, назад)  → OutlinedButton
│
├─ мелкое, в списке или диалоге               → TextButton
│
├─ только иконка
│    ├─ без состояния   → IconButton
│    └─ с состоянием    → IconToggleButton
│
└─ выбор из нескольких вариантов              → SegmentedButton / FilterChip
Часть II

Восемь кейсов

Задача, код как его пишут, что видит пользователь, объяснение через разделы части I и правильный вариант.

Кейс 1. Два заказа вместо одного

Экран оформления: кнопка «Оплатить» отправляет заказ на сервер.

Как пишут
@Composable
fun CheckoutScreen(viewModel: CheckoutViewModel = hiltViewModel()) {
    val state by viewModel.state.collectAsStateWithLifecycle()

    Column {
        OrderSummary(order = state.order)
        Button(
            onClick = { viewModel.pay() },          // защиты от повторного нажатия нет
            modifier = Modifier.fillMaxWidth()
        ) {
            Text(text = "Оплатить")
        }
    }
}
Что видит пользователь
  • Нажал «Оплатить», ничего видимого не произошло — запрос идет секунду
  • Нажал еще раз, на всякий случай
  • Оформились два заказа, списались деньги дважды
  • На медленной сети хватает и одного нажатия с «дребезгом» пальца
Почему

Кнопка ничего не знает о том, что запрос уже идет: enabled по умолчанию true, обработчик срабатывает на каждое нажатие. Состояние «идет оплата» есть во ViewModel, но до кнопки не доведено (раздел 05).

Как надо
Button(
    onClick = { viewModel.pay() },
    enabled = !state.isPaying,                      // одна точка правды
    modifier = Modifier.fillMaxWidth()
) {
    if (state.isPaying) {
        CircularProgressIndicator(
            modifier = Modifier.size(ButtonDefaults.IconSize),
            strokeWidth = 2.dp,
            color = LocalContentColor.current
        )
    } else {
        Text(text = "Оплатить")
    }
}

CheckoutViewModel.kt — вторая половина защиты

fun pay() {
    if (_state.value.isPaying) return               // гонку ловим и здесь тоже
    viewModelScope.launch {
        _state.update { it.copy(isPaying = true) }
        ...
    }
}
ПравилоКнопка, запускающая запрос, обязана иметь enabled, завязанный на состояние запроса. Проверка во ViewModel — вторая линия, а не замена первой.

Кейс 2. Кнопка дергается при загрузке

Та же кнопка с индикатором из кейса 1, но по ширине контента.

Как пишут
Button(onClick = onSave, enabled = !state.isSaving) {
    if (state.isSaving) {
        CircularProgressIndicator(modifier = Modifier.size(16.dp))
    } else {
        Text(text = "Сохранить изменения")
    }
}
Что видит пользователь
  • Нажал «Сохранить изменения»
  • Кнопка резко схлопнулась до кружочка, соседние элементы подпрыгнули
  • После ответа так же резко развернулась обратно
Почему

Кнопка по умолчанию занимает ровно ширину содержимого. Текст из двух слов и спиннер 16 dp — разная ширина, и layout пересчитывается скачком.

Как надо
// вариант 1: ширина задана заранее — самый простой
Button(
    onClick = onSave,
    enabled = !state.isSaving,
    modifier = Modifier.fillMaxWidth()
) { … }

// вариант 2: содержимое меняется, размер сохраняется
Button(onClick = onSave, enabled = !state.isSaving) {
    Box(contentAlignment = Alignment.Center) {
        Text(
            text = "Сохранить изменения",
            modifier = Modifier.alpha(if (state.isSaving) 0f else 1f)   // место занято, текст невидим
        )
        if (state.isSaving) {
            CircularProgressIndicator(
                modifier = Modifier.size(ButtonDefaults.IconSize),
                strokeWidth = 2.dp,
                color = LocalContentColor.current
            )
        }
    }
}
ПравилоСодержимое кнопки меняется — ширина не должна. Либо фиксируется размер, либо старое содержимое остается на месте прозрачным.

Кейс 3. В иконку невозможно попасть

Строка списка сертификатов, справа иконка «поделиться».

Как пишут
Icon(
    painter = painterResource(R.drawable.ds_share),
    contentDescription = null,
    modifier = Modifier
        .size(20.dp)
        .clickable { onShare(certificate.id) }      // область нажатия = размер иконки
)
Что видит пользователь
  • С первого раза попасть не получается, приходится целиться
  • Нет волны нажатия — непонятно, сработало или нет
  • Скринридер называет элемент «изображение», без действия
Почему

20 dp вместо минимальных 48 dp (раздел 06), clickable вместо кнопки — нет ни ripple по форме, ни роли для доступности, ни contentDescription.

Как надо
IconButton(onClick = { onShare(certificate.id) }) {
    Icon(
        painter = painterResource(R.drawable.ds_share),
        contentDescription = "Поделиться сертификатом"
    )
}

IconButton сам держит область 48 × 48 dp, круглый ripple по центру и роль кнопки. Иконка внутри может быть любого размера — цель нажатия от этого не уменьшится.

ПравилоКликабельная иконка — это IconButton с contentDescription, а не Icon с clickable.

Кейс 4. Отключенная кнопка не видна в темной теме

Кнопка «Далее» неактивна, пока форма не заполнена.

Как пишут
Button(
    onClick = onNext,
    enabled = state.isValid,
    colors = ButtonDefaults.buttonColors(
        containerColor = if (state.isValid) Color(0xFF6750A4) else Color(0xFFE0E0E0),
        contentColor = if (state.isValid) Color.White else Color(0xFF9E9E9E)
    )
) { Text(text = "Далее") }
Что видит пользователь
  • В светлой теме выглядит нормально
  • В темной неактивная кнопка — светло-серое пятно на темном фоне, ярче активной
  • После обновления дизайн-системы фирменный цвет поменялся везде, кроме этой кнопки
Почему

ButtonColors уже хранит все четыре цвета, включая disabledContainerColor и disabledContentColor, и переключает их сам по enabled (раздел 03). Условие в коде дублирует эту логику и делает это хуже: мимо темы.

Как надо
Button(onClick = onNext, enabled = state.isValid) {
    Text(text = "Далее")
}

Нужен свой фирменный цвет — задается набором, а не условием:

colors = ButtonDefaults.buttonColors(
    containerColor = MaterialTheme.colorScheme.tertiary,
    contentColor = MaterialTheme.colorScheme.onTertiary
    // disabled-цвета остаются дефолтными и корректны в обеих темах
)
ПравилоСостояние кнопки переключает enabled, а не if в цветах. Цвета из схемы, не хардкодом.

Кейс 5. Своя кнопка из Box

По макету кнопка со скруглением 12 dp и своим фоном — «Button не подходит».

Как пишут
@Composable
fun PrimaryButton(text: String, onClick: () -> Unit, modifier: Modifier = Modifier) {
    Box(
        modifier = modifier
            .clip(RoundedCornerShape(12.dp))
            .background(MaterialTheme.colorScheme.primary)
            .clickable { onClick() }
            .padding(horizontal = 24.dp, vertical = 12.dp),
        contentAlignment = Alignment.Center
    ) {
        Text(text = text, color = MaterialTheme.colorScheme.onPrimary)
    }
}
Что видит пользователь
  • Выглядит как кнопка
  • Нажимается даже во время загрузки: enabled у нее нет вообще
  • Клик срабатывает при промахе в 2 dp мимо текста — и не срабатывает у края
  • Скринридер читает «Оплатить», но не говорит, что это кнопка
  • Нет состояния нажатия и высоты — на пестром фоне кнопка теряется
Почему

Из шести работ раздела 01 самодельная кнопка делает две: фон и форму. Остальные — enabled, ripple по форме, минимальная область нажатия, роль для доступности — отсутствуют молча.

Как надо
@Composable
fun PrimaryButton(
    text: String,
    onClick: () -> Unit,
    modifier: Modifier = Modifier,
    enabled: Boolean = true
) {
    Button(
        onClick = onClick,
        modifier = modifier,
        enabled = enabled,
        shape = RoundedCornerShape(12.dp)        // отличие от дефолта — один параметр
    ) {
        Text(text = text)
    }
}
ПравилоРасхождение с макетом — это параметр (shape, colors, contentPadding), а не повод собирать кнопку заново.

Кейс 6. Текстовая кнопка не выравнивается по краю

Под блоком текста — ссылка-действие «Показать все отзывы».

Как пишут
Column(modifier = Modifier.padding(horizontal = 16.dp)) {
    Text(text = review.text)
    TextButton(onClick = onShowAll) {
        Text(text = "Показать все отзывы")        // текст начинается правее абзаца
    }
}
Что видно на экране
  • Подпись кнопки сдвинута вправо относительно текста над ней на 12 dp
  • Дизайнер приносит скриншот с линейкой, разработчик добавляет offset(x = (-12).dp) — и ломает область нажатия
Почему

У TextButton есть собственные внутренние отступы (ButtonDefaults.TextButtonContentPadding) — они нужны, чтобы область нажатия была достаточной. Визуальный край текста и край компонента не совпадают намеренно.

Как надо
Column(modifier = Modifier.padding(horizontal = 16.dp)) {
    Text(text = review.text)
    TextButton(
        onClick = onShowAll,
        modifier = Modifier.offset(x = -ButtonDefaults.TextButtonContentPadding
            .calculateLeftPadding(LayoutDirection.Ltr))   // компенсируем ровно на величину отступа
    ) {
        Text(text = "Показать все отзывы")
    }
}

Второй вариант, если строка кнопки одна и она первая в колонке — уменьшить внешний отступ самой колонки и добавить его остальным элементам. Что нельзя — сдвигать на подобранное на глаз число: оно не совпадет с отступом при смене типа кнопки.

ПравилоКомпенсируется именно та величина, что задана в ButtonDefaults, а не число из макета.

Кейс 7. Клик по кнопке открывает весь экран

Строка компании в списке: вся строка ведет на экран компании, внутри кнопка «В избранное».

Как пишут
Surface(onClick = { onOpenCompany(company.id) }) {
    Row(verticalAlignment = Alignment.CenterVertically) {
        CompanyLogo(url = company.logoUrl)
        Text(text = company.name, modifier = Modifier.weight(1f))
        Icon(
            painter = painterResource(R.drawable.ds_heart),
            contentDescription = null,
            modifier = Modifier.clickable { onToggleFavorite(company.id) }
        )
    }
}
Что видит пользователь
  • Нажал на сердечко, чтобы добавить компанию в избранное
  • Компания добавилась — и одновременно открылся ее экран
  • Иногда открывается только экран: попал на пиксель мимо иконки
Почему

Modifier.clickable обрабатывает нажатие, но событие продолжает подниматься к родителю. Вложенные кликабельные области требуют, чтобы внутренняя была полноценной кнопкой: IconButton потребляет касание и не пропускает его дальше.

Как надо
Surface(onClick = { onOpenCompany(company.id) }) {
    Row(verticalAlignment = Alignment.CenterVertically) {
        CompanyLogo(url = company.logoUrl)
        Text(text = company.name, modifier = Modifier.weight(1f))
        IconToggleButton(
            checked = company.isFavorite,
            onCheckedChange = { onToggleFavorite(company.id) }
        ) {
            Icon(
                painter = painterResource(
                    if (company.isFavorite) R.drawable.ds_heart_filled else R.drawable.ds_heart
                ),
                contentDescription = if (company.isFavorite) "Убрать из избранного"
                    else "В избранное"
            )
        }
    }
}
ПравилоКнопка внутри кликабельной строки — только настоящая кнопка. Заодно решается область нажатия: 48 dp вместо размера иконки.

Кейс 8. Надпись не влезла

Две кнопки в ряд: «Отмена» и «Подтвердить запись».

Как пишут
Row(horizontalArrangement = Arrangement.spacedBy(12.dp)) {
    OutlinedButton(onClick = onCancel, modifier = Modifier.weight(1f)) {
        Text(text = stringResource(R.string.common_cancel))
    }
    Button(onClick = onConfirm, modifier = Modifier.weight(1f)) {
        Text(text = stringResource(R.string.booking_confirm))
    }
}
Что видит пользователь
  • На русском обе кнопки выглядят правильно
  • На немецком подпись обрезается многоточием: «Terminbestäti…»
  • На арабском текст переносится на две строки, кнопки становятся разной высоты
  • При системном увеличении шрифта то же самое происходит и на русском
Почему

weight(1f) делит ширину поровну независимо от длины подписей, а Text внутри кнопки по умолчанию обрезается в одну строку. Тестируется это только на длинной локали или с крупным системным шрифтом.

Как надо
// вариант 1: кнопки друг под другом — надежнее всего для длинных подписей
Column(verticalArrangement = Arrangement.spacedBy(8.dp)) {
    Button(onClick = onConfirm, modifier = Modifier.fillMaxWidth()) {
        Text(text = stringResource(R.string.booking_confirm))
    }
    TextButton(onClick = onCancel, modifier = Modifier.fillMaxWidth()) {
        Text(text = stringResource(R.string.common_cancel))
    }
}

// вариант 2: остаемся в строке, но ширина по содержимому
Row(horizontalArrangement = Arrangement.spacedBy(12.dp)) {
    OutlinedButton(onClick = onCancel) { Text(text = stringResource(R.string.common_cancel)) }
    Button(onClick = onConfirm, modifier = Modifier.weight(1f)) {
        Text(text = stringResource(R.string.booking_confirm), maxLines = 2)
    }
}
ПравилоПроверка кнопок — на самой длинной локали проекта и при максимальном системном шрифте, а не на русском с дефолтными настройками.

Чеклист ревью

  1. Тип кнопки соответствует весу действия: на экране одна главная.
  2. У кнопки, запускающей запрос, есть enabled по состоянию запроса.
  3. Цвета — из схемы через ButtonDefaults, без if и хардкода.
  4. Кликабельная иконка — IconButton с contentDescription.
  5. Область нажатия не меньше 48 dp.
  6. Иконка внутри кнопки — ButtonDefaults.IconSize и IconSpacing.
  7. Подписи проверены на самой длинной локали и при крупном системном шрифте.
  8. Внутри кликабельной строки — только настоящие кнопки.
Итог

Кнопка — это не прямоугольник с обработчиком, а шесть работ сразу: форма, цвета всех состояний, ripple по форме, минимальная область нажатия, роль для доступности и типографика содержимого. Отсюда два практических вывода: своя кнопка из Box почти всегда теряет половину из них, а расхождение с макетом решается параметром, а не новой реализацией.
