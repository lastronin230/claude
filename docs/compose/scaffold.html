Часть I

Механика: что такое Scaffold

Девять разделов. К концу будет понятно, что именно он делает, какой единственный контракт требует взамен и почему почти все ошибки этой темы сводятся к отступу — не применили или применили дважды.

01 Что это такое

Scaffold — раскладка экрана по ролям. Он знает, что топбар сверху, навигационная панель снизу, снекбар над ними, кнопка действия в углу: расставляет их и сообщает содержимому, сколько места они заняли. Сам ничего не рисует, кроме фона.

┌──────────────────────────────────┐
│ topBar                           │  ← слот: TopAppBar
├──────────────────────────────────┤
│                                  │
│ content(innerPadding)            │  ← лямбда: твой экран
│                                  │     innerPadding = сколько заняли бары и системные полосы
│                        ┌───────┐ │
│                        │  FAB  │ │  ← слот: floatingActionButton
│                        └───────┘ │
│ ┌──────────────────────────────┐ │
│ │ snackbarHost                 │ │  ← слот: сам поднимается над FAB и bottomBar
│ └──────────────────────────────┘ │
├──────────────────────────────────┤
│ bottomBar                        │  ← слот: NavigationBar / BottomAppBar
└──────────────────────────────────┘

02 Слоты и параметры

@Composable
fun Scaffold(
    modifier: Modifier = Modifier,
    topBar: @Composable () -> Unit = {},
    bottomBar: @Composable () -> Unit = {},
    snackbarHost: @Composable () -> Unit = {},
    floatingActionButton: @Composable () -> Unit = {},
    floatingActionButtonPosition: FabPosition = FabPosition.End,
    containerColor: Color = MaterialTheme.colorScheme.background,
    contentColor: Color = contentColorFor(containerColor),
    contentWindowInsets: WindowInsets = ScaffoldDefaults.contentWindowInsets,
    content: @Composable (PaddingValues) -> Unit
)
ПараметрЧто делает
topBar / bottomBar Прижимаются к верху и низу, их высота попадает в innerPadding
snackbarHost Место показа снекбаров; Scaffold сам поднимает их над FAB и нижней панелью
floatingActionButton Кнопка действия; под нее резервируется место, снекбар ее не перекрывает
containerColor / contentColor Фон экрана и цвет содержимого: внутри это Surface
contentWindowInsets Какие системные полосы учитывать при расчете innerPadding
content Лямбда, получающая PaddingValues — это и есть главный контракт

03 innerPadding: единственное, что Scaffold требует от тебя

Scaffold не применяет отступы к содержимому — он их только считает и отдает. Применить обязан ты. Причина в том, что «правильно» зависит от содержимого: обычной колонке нужен Modifier.padding, списку — contentPadding, полноэкранной картинке — ничего.

Scaffold(
    topBar = { TopAppBar(title = { Text(text = "Профиль") }) },
    bottomBar = { NavigationBar { … } }
) { innerPadding ->
    Column(modifier = Modifier.padding(innerPadding)) {
        Text(text = "Содержимое экрана")
    }
}

Компилятор не помогает: неиспользованный параметр лямбды — законный код. Отсюда кейс 1.

04 Список внутри: padding или contentPadding

Modifier.padding(innerPadding)          contentPadding = innerPadding
┌──────────────────────┐                ┌──────────────────────┐
│ topBar               │                │ topBar    ░░░░░░░░░░ │ ← элемент виден под баром
├──────────────────────┤                ├─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┤
│ ┌──────────────────┐ │                │ элемент 2            │
│ │ элемент 1        │ │                │ элемент 3            │
│ │ элемент 2        │ │ список         │ элемент 4            │  список во всю высоту,
│ └──────────────────┘ │ короче экрана  │                      │  сдвинуто только содержимое
└──────────────────────┘                └──────────────────────┘
Scaffold(topBar = { TopAppBar(title = { Text(text = "Лента") }) }) { innerPadding ->
    LazyColumn(
        modifier = Modifier.consumeWindowInsets(innerPadding),
        contentPadding = innerPadding
    ) {
        items(items = items, key = { it.id }) { item -> FeedRow(item = item) }
    }
}

consumeWindowInsets сообщает вложенным элементам, что эта часть системных отступов уже учтена. Без него дочерний элемент, который сам добавляет отступ под клавиатуру или навигационную полосу, добавит его повторно — кейс 7.

05 Системные отступы: что Scaffold знает

В innerPadding складываются две вещи: высоты слотов и системные полосы из contentWindowInsets. По умолчанию это статусбар и навигационная полоса.

ЗадачаКак
Обычный экран во весь экранНичего не менять: ScaffoldDefaults.contentWindowInsets
Экран сам управляет отступами (фон под статусбаром)contentWindowInsets = WindowInsets(0, 0, 0, 0)
Поле ввода поднимается над клавиатуройModifier.imePadding() на нужной части содержимого

06 Сворачиваемый топбар: два обязательных куска

Поведение прокрутки живет не в баре, а в связке «объект поведения + подключение к прокрутке на Scaffold». Забыть второй кусок легко — кейс 4.

val scrollBehavior = TopAppBarDefaults.enterAlwaysScrollBehavior()

Scaffold(
    modifier = Modifier.nestedScroll(scrollBehavior.nestedScrollConnection),   // 1. подключение
    topBar = {
        TopAppBar(
            title = { Text(text = "Лента") },
            scrollBehavior = scrollBehavior                                    // 2. передача бару
        )
    }
) { innerPadding ->
    LazyColumn(
        modifier = Modifier.consumeWindowInsets(innerPadding),
        contentPadding = innerPadding
    ) { … }
}
ПоведениеЧто происходит при прокрутке
pinnedScrollBehaviorБар остается, но меняет цвет
enterAlwaysScrollBehaviorУезжает вверх, возвращается при первом движении вниз
exitUntilCollapsedScrollBehaviorБольшой бар сжимается до обычного

07 Snackbar

Показ снекбара — suspend-функция, поэтому нужны две вещи: состояние хоста и корутинный скоуп.

val snackbarHostState = remember { SnackbarHostState() }
val scope = rememberCoroutineScope()

Scaffold(
    snackbarHost = { SnackbarHost(hostState = snackbarHostState) },
    floatingActionButton = {
        FloatingActionButton(
            onClick = { scope.launch { snackbarHostState.showSnackbar(message = "Сохранено") } }
        ) {
            Icon(imageVector = Icons.Default.Add, contentDescription = "Добавить")
        }
    }
) { innerPadding -> … }

08 Цвета: Scaffold — это Surface

Внутри Scaffold — Surface на весь экран с containerColor (по умолчанию colorScheme.background) и парным contentColor. Отсюда: фон экрана меняется параметром, а не обертыванием во второй Surface, и текст внутри уже получает читаемый цвет.

Scaffold(containerColor = MaterialTheme.colorScheme.surfaceContainerLowest) { … }

09 Когда Scaffold не нужен

Есть ли у экрана хоть один слот: топбар, нижняя панель, FAB, снекбар?
│
├─ НЕТ → Column / Box плюс Modifier.windowInsetsPadding, если экран во весь экран
│        (диалог, шторка, вкладка внутри уже существующего Scaffold)
│
└─ ДА  → Scaffold, один на экран

         └─ Нужна адаптивная навигация (рельса на планшете, панель снизу на телефоне)?

Часть II

Восемь кейсов

Задача, код как его пишут, что видно на экране, объяснение через разделы части I и правильный вариант.

Кейс 1. Первая строка спрятана под топбаром

Экран профиля: заголовок сверху, нижняя навигация, контент между ними.

Как пишут
@Composable
fun ProfileScreen(state: ProfileUiState) {
    Scaffold(
        topBar = { TopAppBar(title = { Text(text = "Профиль") }) },
        bottomBar = { AppNavigationBar() }
    ) { _ ->                                   // параметр проигнорирован
        Column {
            Text(text = state.name, style = MaterialTheme.typography.headlineSmall)
            Text(text = state.phone)
            ProfileActions(actions = state.actions)
        }
    }
}
Что видно на экране
  • Имя пользователя наполовину скрыто топбаром
  • Последний пункт списка действий уехал под нижнюю панель и не нажимается
  • На устройствах с жестовой навигацией внизу срезается еще полоса
Почему

Scaffold отступы только считает, а применяет их содержимое (раздел 03). Компилятор молчит: _ вместо имени параметра — законный код.

Как надо
) { innerPadding ->
    Column(modifier = Modifier.padding(innerPadding)) { … }
}
ПравилоСимвол _ в лямбде Scaffold — повод остановиться и объяснить себе, почему отступ не нужен.

Кейс 2. Список кончается раньше экрана

Лента компаний под полупрозрачным топбаром.

Как пишут
Scaffold(topBar = { TopAppBar(title = { Text(text = "Лента") }) }) { innerPadding ->
    LazyColumn(modifier = Modifier.padding(innerPadding)) {
        items(items = state.items, key = { it.id }) { company ->
            CompanyRow(company = company)
        }
    }
}
Что видно на экране
  • Отступ вроде правильный, ничего не перекрыто
  • Элементы обрезаются ровно по нижней кромке топбара, а не уезжают под него
  • Между баром и первым элементом видна полоса фона — эффект «список в коробке»
  • Скроллбар начинается не от края экрана
Почему

Modifier.padding уменьшает сам список: он заканчивается там, где начинается бар. contentPadding оставляет список во всю высоту и сдвигает только содержимое внутри — тогда элементы прокручиваются под баром, как задумано в Material (раздел 04).

Как надо
LazyColumn(
    modifier = Modifier.consumeWindowInsets(innerPadding),
    contentPadding = innerPadding
) {
    items(items = state.items, key = { it.id }) { company ->
        CompanyRow(company = company)
    }
}
ПравилоПрокручиваемому содержимому — contentPadding, непрокручиваемому — Modifier.padding.

Кейс 3. Контент опустился на две высоты статусбара

Экран с вкладками, каждая вкладка написана как самостоятельный экран.

Как пишут
@Composable
fun WalletTabsScreen() {
    Scaffold(topBar = { TopAppBar(title = { Text(text = "Кошелек") }) }) { outerPadding ->
        Column(modifier = Modifier.padding(outerPadding)) {
            TabRow(selectedTabIndex = selected) { … }
            when (selected) {
                0 -> CardsTab()          // а внутри — свой Scaffold
                1 -> HistoryTab()
            }
        }
    }
}

@Composable
private fun CardsTab() {
    Scaffold { innerPadding ->               // второй каркас на том же экране
        LazyColumn(contentPadding = innerPadding) { … }
    }
}
Что видно на экране
  • Между вкладками и первым элементом зияет пустая полоса
  • Внизу такой же лишний зазор над навигационной полосой
  • На устройствах с большим вырезом расхождение с макетом еще заметнее
Почему

Вложенный Scaffold считает системные полосы заново, ничего не зная о том, что внешний их уже учел. Высота статусбара попадает в отступ дважды (раздел 05).

Как надо
@Composable
private fun CardsTab(contentPadding: PaddingValues) {   // каркас один на экран
    LazyColumn(contentPadding = contentPadding) { … }
}

Если вложенный каркас нужен по устройству кода, у него отключаются системные полосы: contentWindowInsets = WindowInsets(0, 0, 0, 0).

ПравилоОдин экран — один Scaffold.

Кейс 4. Топбар отказывается сворачиваться

Длинная лента: при прокрутке вниз шапка должна уезжать.

Как пишут
val scrollBehavior = TopAppBarDefaults.enterAlwaysScrollBehavior()

Scaffold(                                        // подключения к прокрутке нет
    topBar = {
        TopAppBar(title = { Text(text = "Лента") }, scrollBehavior = scrollBehavior)
    }
) { innerPadding ->
    LazyColumn(contentPadding = innerPadding) { … }
}
Что видно на экране
  • Список прокручивается нормально
  • Шапка стоит на месте, хотя по макету должна уезжать
  • Ни ошибки, ни предупреждения — код выглядит правильным
Почему

Объект поведения умеет менять вид бара, но не знает, что происходит с прокруткой, пока его не подключили к дереву через nestedScroll (раздел 06). Кусков всегда два, а забывается обычно первый.

Как надо
Scaffold(
    modifier = Modifier.nestedScroll(scrollBehavior.nestedScrollConnection),
    topBar = { TopAppBar(title = { Text(text = "Лента") }, scrollBehavior = scrollBehavior) }
) { … }
ПравилоПоведение топбара — это всегда пара: создать и подключить. Один scrollBehavior на экран, создается через remember внутри TopAppBarDefaults.

Кейс 5. Снекбар выезжает под кнопкой

Список адресов, кнопка добавления в правом нижнем углу.

Как пишут
Scaffold(
    snackbarHost = { SnackbarHost(hostState = snackbarHostState) }
) { innerPadding ->
    Box(modifier = Modifier.padding(innerPadding)) {
        AddressList(addresses = state.addresses)
        FloatingActionButton(                          // кнопка внутри содержимого
            onClick = onAdd,
            modifier = Modifier.align(Alignment.BottomEnd).padding(16.dp)
        ) { Icon(imageVector = Icons.Default.Add, contentDescription = "Добавить") }
    }
}
Что видно на экране
  • Снекбар вылезает прямо под кнопкой и перекрывается ею
  • Последний адрес в списке навсегда спрятан под кнопкой, до него не доскроллить
  • На жестовой навигации кнопка налезает на системную полосу
Почему

В слоте Scaffold делает три вещи разом: резервирует место в innerPadding, поднимает над кнопкой снекбар и учитывает системные отступы снизу. В Box все это теряется.

Как надо
Scaffold(
    snackbarHost = { SnackbarHost(hostState = snackbarHostState) },
    floatingActionButton = {
        FloatingActionButton(onClick = onAdd) {
            Icon(imageVector = Icons.Default.Add, contentDescription = "Добавить")
        }
    }
) { innerPadding ->
    AddressList(addresses = state.addresses, contentPadding = innerPadding)
}
ПравилоВсе, для чего у Scaffold есть слот, кладется в слот, а не в содержимое.

Кейс 6. Снекбар не показывается вообще

Сохранение настроек: после успеха показать подтверждение.

Как пишут
Scaffold(
    snackbarHost = { SnackbarHost(hostState = SnackbarHostState()) }   // новый объект каждый прогон
) { innerPadding ->
    SettingsContent(
        onSave = { scope.launch { snackbarHostState.showSnackbar("Сохранено") } },
        modifier = Modifier.padding(innerPadding)
    )
}
Что видно на экране
  • Настройки сохраняются, запрос уходит
  • Подтверждение не появляется никогда
  • Иногда мелькает и мгновенно пропадает
Почему

Состояние хоста создается заново на каждом прогоне: то, чему отдали сообщение, и то, что сейчас на экране, — разные объекты. Классическая ошибка «состояние без remember».

Как надо
val snackbarHostState = remember { SnackbarHostState() }

Scaffold(snackbarHost = { SnackbarHost(hostState = snackbarHostState) }) { … }

Вторая половина той же темы — показ снекбара по состоянию ошибки без гашения события: сообщение повторяется после поворота. Разбор в статье про сайд-эффекты, кейс 6.

ПравилоSnackbarHostState — всегда через remember и всегда снаружи слота.

Кейс 7. Поле ввода подпрыгивает выше клавиатуры

Экран чата с компанией: поле ввода внизу должно подниматься над клавиатурой.

Как пишут
Scaffold(
    contentWindowInsets = ScaffoldDefaults.contentWindowInsets.add(WindowInsets.ime)
) { innerPadding ->
    Column(
        modifier = Modifier
            .padding(innerPadding)
            .imePadding()                    // клавиатура учтена второй раз
    ) {
        MessagesList(messages = state.messages, modifier = Modifier.weight(1f))
        MessageInput(onSend = onSend)
    }
}
Что видно на экране
  • Открыл клавиатуру
  • Поле ввода подскочило на высоту клавиатуры сверх нее — между ними пустая полоса в пол-экрана
  • Часть переписки уехала за верхний край
Почему

Один и тот же отступ применен снаружи и внутри. Правило общее для всех insets: если родитель уже учел полосу, потомок не должен учитывать ее повторно — а узнать об этом потомок может только через consumeWindowInsets (раздел 04).

Как надо
Scaffold { innerPadding ->                 // insets по умолчанию, клавиатура не в них
    Column(
        modifier = Modifier
            .padding(innerPadding)
            .consumeWindowInsets(innerPadding)
            .imePadding()                  // единственное место, где учитывается клавиатура
    ) { … }
}
ПравилоКаждая системная полоса учитывается ровно один раз. Двойной зазор — всегда «применили дважды», а не «применили не там».

Кейс 8. Лишний Surface поверх фона

Экран настроек: фон должен быть чуть светлее обычного.

Как пишут
Scaffold(topBar = { TopAppBar(title = { Text(text = "Настройки") }) }) { innerPadding ->
    Surface(                                        // второй Surface поверх фона Scaffold
        modifier = Modifier.fillMaxSize().padding(innerPadding),
        color = MaterialTheme.colorScheme.surfaceContainerLowest
    ) {
        SettingsList(items = state.items)
    }
}
Что видно на экране
  • Фон выглядит правильно
  • Под топбаром и над нижней панелью просвечивает старый цвет background — экран будто в рамке
  • Лишний слой в иерархии, а в темной теме еще и сложение тональных высот
Почему

Scaffold внутри уже Surface на весь экран (раздел 08). Второй накрывает только область содержимого, поэтому в зонах слотов остается прежний цвет.

Как надо
Scaffold(
    topBar = { TopAppBar(title = { Text(text = "Настройки") }) },
    containerColor = MaterialTheme.colorScheme.surfaceContainerLowest
) { innerPadding ->
    SettingsList(items = state.items, contentPadding = innerPadding)
}
ПравилоФон экрана задается параметром containerColor, а не оберткой. Подробнее про слои — в статье про Surface.

Итог

Scaffold берет на себя размещение баров, снекбара и кнопки действия и считает, сколько места они заняли. Все, что он просит взамен, — применить innerPadding: колонке через Modifier.padding, списку через contentPadding. Ошибки этой темы почти все сводятся к одному из двух: отступ не применили или применили дважды.
