Механика: как устроено поле ввода

Восемь разделов подряд. К концу будет понятно, почему поле не печатает само, что происходит с курсором при форматировании и кто отвечает за клавиатуру и фокус.

02 Поле ничего не хранит само

Главное отличие от EditText: у поля в Compose нет внутреннего текста. Оно показывает то, что ему передали в value, и сообщает о попытке ввода через onValueChange. Замкнуть круг обязан ты.

пользователь нажал букву
        │
        ▼
  onValueChange("А")  →  твое состояние обновилось
        │                        │
        │                        ▼
        └────────────  value = "А"  →  поле перерисовалось с новым текстом

разомкни эту петлю в любом месте — поле перестанет печатать
var name by rememberSaveable { mutableStateOf("") }

OutlinedTextField(
    value = name,
    onValueChange = { name = it },
    label = { Text(text = "Имя") },
    singleLine = true,
    modifier = Modifier.fillMaxWidth()
)

Это то же правило, что и у любого состояния: remember хранит, mutableStateOf уведомляет. Поле ввода просто делает нарушение заметным сразу — кейс 1.

03 Состояние и курсор: три уровня API

Строки хватает, пока текст меняет только пользователь. Как только текст правится программно — маска, фильтр, автоподстановка кода из SMS, — выясняется, что кроме текста есть еще позиция курсора и выделение, и кто-то должен ими управлять.

Разберем на одной задаче: поле кода из SMS. Четыре цифры, буквы вводить нельзя, код может прийти автоматически и подставиться сам.

Уровень 1: String — текста достаточно

@Composable
fun CodeFieldSimple() {
    var code by rememberSaveable { mutableStateOf("") }

    OutlinedTextField(
        value = code,
        onValueChange = { input ->
            code = input.filter { it.isDigit() }.take(CODE_LENGTH)
        },
        keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.NumberPassword)
    )
}

Пока пользователь просто печатает, все работает: он дописывает символы в конец, и курсор там же. Но фильтр уже показывает трещину — попробуй вставить в середину лишнюю букву:

было:    12|34          курсор после второго символа
вставили «a»:  12a34    onValueChange получил "12a34"
фильтр вернул: 1234     строка та же, что была до вставки
поле видит:    1234     длина не изменилась, но это ДРУГОЙ объект

куда ставить курсор — поле не знает. Ставит в конец: 1234|

В String позиции курсора нет в принципе. Поле восстанавливает ее эвристикой, и любая программная правка эту эвристику ломает — отсюда кейс 2.

Уровень 2: TextFieldValue — текст плюс курсор

Теперь добавим автоподстановку: код пришел из SMS, его надо вставить в поле.

// со String: текст подставился, а курсор оказался перед ним
LaunchedEffect(smsCode) {
    if (smsCode != null) code = smsCode      // курсор: |1234
}
@Composable
fun CodeFieldWithValue(smsCode: String?) {
    var field by remember { mutableStateOf(TextFieldValue(text = "")) }

    LaunchedEffect(smsCode) {
        if (smsCode != null) {
            field = TextFieldValue(
                text = smsCode,
                selection = TextRange(smsCode.length)      // курсор ставим сами — в конец
            )
        }
    }

    OutlinedTextField(
        value = field,
        onValueChange = { new ->
            val digits = new.text.filter { it.isDigit() }.take(CODE_LENGTH)
            field = new.copy(
                text = digits,
                selection = TextRange(digits.length.coerceAtMost(new.selection.end))
            )
        },
        keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.NumberPassword)
    )
}
Поле TextFieldValueЧто означает
textсам текст
selection: TextRange курсор, если start == end; иначе выделенный кусок
composition кусок, который сейчас набирает клавиатура (T9, подсказки) — трогать не нужно

Частые значения: TextRange(0) — курсор в начало, TextRange(text.length) — в конец, TextRange(0, text.length) — выделить все (удобно, когда поле открывается с предзаполненным значением, которое пользователь скорее заменит целиком, чем отредактирует).

Ошибка 1: rememberSaveable без Saver

rememberSaveable кладет значение в Bundle, а по умолчанию умеет только то, что Bundle принимает: примитивы, String, Parcelable. TextFieldValue в этот список не входит, и приложение падает при первом же сохранении состояния: «cannot be saved using the current SaveableStateRegistry». Saver для него уже написан, его нужно передать.

var field by rememberSaveable { mutableStateOf(TextFieldValue("")) }   // упадет
var field by rememberSaveable(stateSaver = TextFieldValue.Saver) {     // сохранит текст и курсор
    mutableStateOf(TextFieldValue(""))
}

Параметр именно stateSaver, а не saver: сохраняется MutableState<TextFieldValue>, а не голое значение. Для String saver не нужен вовсе, а rememberTextFieldState() сохраняет себя сам.

Ошибка 2: пересоздание значения целиком

В onValueChange нельзя собирать TextFieldValue заново из одного текста: поле selection при этом сбрасывается в ноль, и курсор прыгает в начало на каждом введенном символе.

field = TextFieldValue(digits)                      // selection потерян
field = new.copy(text = digits)                     // остальные поля сохранены

Уровень 3: TextFieldState — состояние живет в объекте поля

Проблема второго уровня видна в коде выше: каждое нажатие проходит полный круг «поле отдало значение → я его поправил → вернул обратно». Между этими шагами может прийти новое событие, и тогда правки накладываются друг на друга — отсюда пропадающие символы при быстром наборе.

Новый API убирает круг: состояние принадлежит полю, а ты описываешь правила, по которым ввод принимается.

@Composable
fun CodeFieldWithState(smsCode: String?) {
    val state = rememberTextFieldState()                 // текст + курсор внутри объекта

    LaunchedEffect(smsCode) {
        if (smsCode != null) {
            state.setTextAndPlaceCursorAtEnd(smsCode)    // подстановка одной строкой
        }
    }

    BasicTextField(
        state = state,                                   // ни value, ни onValueChange
        inputTransformation = DigitsOnly(maxLength = CODE_LENGTH),
        keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.NumberPassword)
    )
}

private class DigitsOnly(private val maxLength: Int) : InputTransformation {
    override fun TextFieldBuffer.transformInput() {
        if (!asCharSequence().all(Char::isDigit)) revertAllChanges()   // ввод отклонен целиком
        if (length > maxLength) revertAllChanges()
    }
}

Читается состояние как state.text, правится через state.edit { }:

val code: String = state.text.toString()

state.edit {
    replace(0, length, "0000")
    placeCursorAtEnd()
}
Про версии

TextFieldState пришел сначала в BasicTextField (foundation), затем перегрузки со state появились у TextField и OutlinedTextField в material3. Имена методов трансформаций между версиями менялись — сверяйся с той, что стоит в libs.versions.toml, а не с первой попавшейся статьей.

Что выбрать

УровеньБерем, когдаЦена
String обычная форма: имя, адрес, комментарий. Текст меняет только пользователь Программная правка роняет курсор
TextFieldValue нужна подстановка текста, выделение «все», управление курсором Курсор ведешь сам в каждой ветке onValueChange
TextFieldState новый код: фильтрация ввода, маски, быстрый набор Требует свежей версии и другого мышления: правила вместо обработчика

Практический ориентир: по умолчанию String. Как только появляется строка вида value = чтоТоИзменилось(state) или подстановка текста извне — это сигнал переходить на уровень выше, а не подпирать эвристику поля.

05 Фокус

Фокус — это ответ на вопрос «куда попадет следующий символ». В XML им управлял сам EditText через requestFocus() и nextFocusDown. В Compose тем же занимаются четыре инструмента, и каждый отвечает за свою половину задачи.

ИнструментЗадачаОткуда берется
FocusRequesterпоставить фокус в конкретное поле программно remember { FocusRequester() }
LocalFocusManagerперевести фокус дальше или снять совсем LocalFocusManager.current
Modifier.onFocusChangedузнать, что поле получило или потеряло фокус модификатор на поле
LocalSoftwareKeyboardControllerпоказать или скрыть клавиатуру .current, nullable

Пример 1: автофокус при открытии экрана

@Composable
fun CodeScreen(viewModel: CodeViewModel = hiltViewModel()) {
    val state by viewModel.state.collectAsStateWithLifecycle()
    val focusRequester = remember { FocusRequester() }
    val keyboard = LocalSoftwareKeyboardController.current

    LaunchedEffect(Unit) {
        focusRequester.requestFocus()      // фокус — после того, как поле попало в дерево
        keyboard?.show()                   // на части устройств клавиатура сама не открывается
    }

    OutlinedTextField(
        value = state.code,
        onValueChange = viewModel::onCodeChange,
        modifier = Modifier.focusRequester(focusRequester),   // связь: реквестер ↔ поле
        keyboardOptions = KeyboardOptions(
            keyboardType = KeyboardType.NumberPassword,
            imeAction = ImeAction.Done
        )
    )
}

Две строчки связаны: FocusRequester ничего не делает сам по себе, пока он не привязан модификатором focusRequester(…) к конкретному полю. Забыли модификатор — падение IllegalStateException: FocusRequester is not initialized, то же самое сообщение, что и при вызове из тела composable (кейс 7).

Пример 2: переход между полями формы

Кнопка на клавиатуре должна вести к следующему полю, а на последнем — отправлять форму. Это две настройки: imeAction говорит, что нарисовать на кнопке, keyboardActions — что при нажатии сделать.

@Composable
fun DeliveryForm(state: DeliveryUiState, viewModel: DeliveryViewModel) {
    val focusManager = LocalFocusManager.current

    Column(verticalArrangement = Arrangement.spacedBy(12.dp)) {
        OutlinedTextField(
            value = state.street,
            onValueChange = viewModel::onStreetChange,
            label = { Text(text = "Улица") },
            singleLine = true,
            keyboardOptions = KeyboardOptions(imeAction = ImeAction.Next),
            keyboardActions = KeyboardActions(
                onNext = { focusManager.moveFocus(FocusDirection.Down) }
            )
        )

        OutlinedTextField(
            value = state.house,
            onValueChange = viewModel::onHouseChange,
            label = { Text(text = "Дом") },
            singleLine = true,
            keyboardOptions = KeyboardOptions(
                keyboardType = KeyboardType.Number,
                imeAction = ImeAction.Next
            ),
            keyboardActions = KeyboardActions(
                onNext = { focusManager.moveFocus(FocusDirection.Down) }
            )
        )

        OutlinedTextField(
            value = state.comment,
            onValueChange = viewModel::onCommentChange,
            label = { Text(text = "Комментарий курьеру") },
            keyboardOptions = KeyboardOptions(imeAction = ImeAction.Done),
            keyboardActions = KeyboardActions(
                onDone = {
                    focusManager.clearFocus()      // фокус снят, клавиатура закрылась
                    viewModel.submit()
                }
            )
        )
    }
}
ВызовЧто делает
moveFocus(FocusDirection.Down)следующее поле по порядку в дереве
moveFocus(FocusDirection.Next)то же, но с учетом направления письма (RTL)
clearFocus()снять фокус со всех полей; клавиатура закрывается сама
clearFocus(force = true)снять даже у поля, которое фокус удерживает

clearFocus() обычно достаточно, чтобы клавиатура ушла: она скрывается вслед за потерей фокуса. keyboard?.hide() отдельно нужен в редком случае — когда клавиатуру надо убрать, а фокус в поле оставить.

Пример 3: реакция на получение и потерю фокуса

Два типовых сценария. Первый — валидация на выходе из поля вместо проверки на каждый символ (кейс 5). Второй — выделить весь текст при входе, чтобы предзаполненное значение можно было заменить одним нажатием.

var field by rememberSaveable(stateSaver = TextFieldValue.Saver) {
    mutableStateOf(TextFieldValue(text = state.savedAmount))
}
var wasFocused by rememberSaveable { mutableStateOf(false) }

OutlinedTextField(
    value = field,
    onValueChange = { field = it },
    label = { Text(text = "Сумма") },
    isError = state.amountError != null,
    modifier = Modifier.onFocusChanged { focusState ->
        if (focusState.isFocused) {
            wasFocused = true
            field = field.copy(selection = TextRange(0, field.text.length))   // выделили все
        } else if (wasFocused) {
            viewModel.validateAmount(field.text)                             // проверка на выходе
        }
    }
)

Пример 4: снять фокус тапом по пустому месту

На экране с формой пользователь ожидает, что тап вне полей закроет клавиатуру. Само это не происходит: поле не теряет фокус, пока фокус не забрали.

val focusManager = LocalFocusManager.current

Column(
    modifier = Modifier
        .fillMaxSize()

Именно pointerInput, а не clickable: последний добавит контейнеру ripple на весь экран и роль кнопки для скринридера — экран начнет читаться как одна большая кнопка.

Фокус и списки

Поле внутри LazyColumn теряет фокус, когда уезжает за пределы экрана: элемент уходит из композиции вместе со всем своим состоянием. Если форма длинная и поля должны переживать прокрутку — это повод либо не делать ее лениво (Column с verticalScroll), либо держать значения во ViewModel.

06 Маски и фильтрация

Две разные задачи, которые постоянно смешивают в одну. Разница в том, что именно меняется — значение или только картинка.

ФильтрацияМаска

Примероставить одни цифры, не длиннее 11 показать +7 (999) 123-45-67 при значении 79991234567
Чемфильтр в onValueChange или InputTransformation VisualTransformation или OutputTransformation
Что уйдет на серверто, что в состоянии: чистые цифры в обоих случаях

Фильтрация: что можно ввести

OutlinedTextField(
    value = phone,
    onValueChange = { input ->
        phone = input.filter { it.isDigit() }.take(PHONE_LENGTH)   // лишнее просто не доедет
    },
    keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Phone)
)

Фильтр обязан быть идемпотентным и разрешать удаление. Самая частая ошибка — условие, которое запрещает присвоение целиком:

onValueChange = { input ->
    if (input.length == CODE_LENGTH) code = input      // стереть символ невозможно:
}                                                      // строка короче условия не проходит
onValueChange = { input ->
    if (input.all { it.isDigit() }) phone = input      // вставка «+7 999…» из буфера
}                                                      // отбрасывается целиком, молча
onValueChange = { input ->
    phone = input.filter { it.isDigit() }.take(PHONE_LENGTH)   // из вставки берем то, что подходит
}

Разница принципиальная: filter чистит ввод, а if его отвергает. Пользователь, вставляющий номер из мессенджера, видит в первом случае номер, во втором — ничего, и не понимает почему.

Маска: как устроен VisualTransformation

У интерфейса один метод, который возвращает две вещи:

fun interface VisualTransformation {
    fun filter(text: AnnotatedString): TransformedText
}

class TransformedText(
    val text: AnnotatedString,        // что показать на экране
    val offsetMapping: OffsetMapping  // как пересчитать позиции курсора между строками
)

Вся сложность — во втором. Строки разной длины, а курсор и выделение существуют в обеих:

значение:     7  9  9  9  1  2  3  4  5  6  7          11 символов
              │  │  │  │  │  │  │  │  │  │  │
показано:  +  7     (  9  9  9  )     1  2  3  -  4  5  -  6  7    18 символов

пользователь ставит курсор после «999» на экране — позиция 7
в значении это позиция 4. Пересчет в обе стороны и есть OffsetMapping
Почему это падает

Если OffsetMapping вернет позицию за пределами строки, поле упадет с IndexOutOfBoundsException в момент установки курсора — не при вводе, а при тапе в конкретное место. Такой баг легко не заметить в тестах: на обычном наборе с конца строки он не воспроизводится.

PhoneVisualTransformation.kt — маска, которая не ломает курсор

private const val PHONE_MASK = "+# (###) ###-##-##"

class PhoneVisualTransformation : VisualTransformation {

    override fun filter(text: AnnotatedString): TransformedText {
        val digits = text.text.filter { it.isDigit() }
        val formatted = format(digits = digits)

        val mapping = object : OffsetMapping {
            // из позиции в значении — в позицию на экране
            override fun originalToTransformed(offset: Int): Int {
                if (offset <= 0) return 0
                var seen = 0
                formatted.forEachIndexed { index, char ->
                    if (char.isDigit()) {
                        seen++
                        if (seen == offset) return index + 1
                    }
                }
                return formatted.length
            }

            // обратно: сколько цифр стоит левее этой позиции на экране
            override fun transformedToOriginal(offset: Int): Int =
                formatted.take(offset.coerceIn(0, formatted.length)).count { it.isDigit() }
        }

        return TransformedText(text = AnnotatedString(formatted), offsetMapping = mapping)
    }

    private fun format(digits: String): String {
        if (digits.isEmpty()) return ""
        return buildString {
            var digitIndex = 0
            for (char in PHONE_MASK) {
                if (digitIndex >= digits.length) break
                if (char == '#') append(digits[digitIndex++]) else append(char)
            }
        }
    }
}

Маппинг здесь считает цифры, а не складывает подобранные числа (offset + 4, offset + 6 и так далее). Это важно: подобранные сдвиги придется пересчитывать при любой правке маски, и ошибка в одном из них даст падение на одной конкретной позиции курсора.

Готовая маска в библиотеке ровно одна — для пароля, и устроена она так же:

OutlinedTextField(
    value = password,
    onValueChange = { password = it },
    visualTransformation = PasswordVisualTransformation(),   // точки вместо символов
    keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Password)
)

Маска в новом API: OutputTransformation

В API со TextFieldState маппинг писать не нужно — ты правишь буфер, а пересчет позиций рантайм делает сам:

val state = rememberTextFieldState()

BasicTextField(
    state = state,
    inputTransformation = InputTransformation.maxLength(PHONE_LENGTH),   // фильтрация
    outputTransformation = PhoneOutputTransformation,                    // маска
    keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Phone)
)

private object PhoneOutputTransformation : OutputTransformation {
    override fun TextFieldBuffer.transformOutput() {
        if (length > 0) insert(0, "+")
        if (length > 2) insert(2, " (")
        if (length > 7) insert(7, ") ")
        if (length > 12) insert(12, "-")
        if (length > 15) insert(15, "-")
    }
}

Каждая вставка сдвигает последующие индексы — поэтому проверки идут по уже изменившейся длине. Имена методов между версиями менялись, сверяйся с той, что стоит в проекте.

Денежное поле: где обычно ошибаются

// значение хранит отформатированную строку
onValueChange = { input ->
    amount = formatWithSpaces(input)      // "1 234" в состоянии
}
// перед отправкой приходится чистить в каждом месте вызова
repository.pay(amount = amount.replace(" ", "").toLong())
var amount by rememberSaveable { mutableStateOf("") }          // "1234" — чистое значение

OutlinedTextField(
    value = amount,
    onValueChange = { input -> amount = input.filter { it.isDigit() }.take(AMOUNT_MAX_DIGITS) },
    visualTransformation = ThousandsVisualTransformation(),     // "1 234" только на экране
    keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Number)
)
Дробная часть и локаль

Если поле принимает копейки, разделитель зависит от локали клавиатуры: на русской это запятая, на английской — точка. Принимать нужно оба символа и нормализовать при чтении, а KeyboardType.Decimal ставить вместо Number — иначе на части клавиатур разделителя просто не будет на экране.

Что выбрать

ЗадачаИнструмент
Только цифры, ограничение длиныфильтр в onValueChange / InputTransformation
Телефон, карта, дата с разделителямиVisualTransformation / OutputTransformation
Пароль точкамиPasswordVisualTransformation()
Разделители тысячVisualTransformation, значение остается чистым
Верхний регистр, запрет пробеловфильтр: input.uppercase(), input.filterNot { it.isWhitespace() }

Правило, к которому все сводится: в состоянии лежит то, что уйдет на сервер. Все, что добавлено для читаемости — скобки, пробелы, дефисы, точки пароля, — живет на слое отображения и в значение не попадает.

08 Дерево решений

Нужно поле ввода. Какое?
│
├─ обычная форма: label, ошибка, подсказка
│    ├─ поля идут подряд, нужна четкая граница → OutlinedTextField
│    └─ поле одно внутри блока                 → TextField
│
├─ оформление свое: поиск в шапке, код из SMS, чат
│    └─ BasicTextField + свой decorationBox
│
└─ что хранить?
     ├─ текст меняется только пользователем      → String
     ├─ текст правится программно, есть маска    → TextFieldValue
     └─ новый код, нужна фильтрация ввода        → TextFieldState

Кейс 1. Поле не печатает

Форма промокода: одно поле и кнопка «Применить».

Как пишут
@Composable
fun PromoCodeField(onApply: (String) -> Unit) {
    var code by mutableStateOf("")            // забыли remember

    OutlinedTextField(
        value = code,
        onValueChange = { code = it },
        label = { Text(text = "Промокод") }
    )
}
Что видит пользователь
  • Клавиатура открылась, нажатия проходят
  • В поле не появляется ни одного символа
  • Иногда первая буква мелькает и пропадает
Почему

Петля из раздела 02 разомкнута в самом начале: mutableStateOf без remember пересоздается на каждой рекомпозиции, а ввод эту рекомпозицию и запускает. Значение записалось — и тут же потерялось вместе с состоянием.

Второй способ разомкнуть ту же петлю — пустой обработчик:

OutlinedTextField(value = code, onValueChange = { })   // поле навсегда останется пустым
Как надо
var code by rememberSaveable { mutableStateOf("") }
ПравилоПоле не печатает — смотри петлю: состояние под remember и onValueChange, который это состояние меняет.

Кейс 2. Курсор прыгает в конец строки

Поле телефона с маской: пользователь должен видеть +7 (999) 123-45-67.

Как пишут
var phone by rememberSaveable { mutableStateOf("") }

OutlinedTextField(
    value = formatPhone(phone),                       // форматируем прямо в value
    onValueChange = { input ->
        phone = input.filter { it.isDigit() }         // а храним цифры
    },
    keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Phone)
)
Что видит пользователь
  • Ввел номер до конца — выглядит правильно
  • Заметил опечатку в середине, ткнул туда и стер цифру
  • Курсор мгновенно улетел в конец строки, следующая цифра дописалась не туда
  • Исправить номер в середине физически невозможно
Почему

В value уходит строка, которую поле не видело: длина изменилась, а позиции курсора в String нет вообще (раздел 03). Поле вынуждено поставить курсор в конец.

Как надо
// маска — на отображении, состояние остается чистым
OutlinedTextField(
    value = phone,                                    // только цифры
    onValueChange = { input ->
        phone = input.filter { it.isDigit() }.take(PHONE_LENGTH)
    },
    visualTransformation = PhoneVisualTransformation(),   // рисует +7 (999) 123-45-67
    keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.Phone)
)

Если текст все-таки правится программно — курсор нужно вести самому, и тогда состояние хранится как TextFieldValue:

var field by remember { mutableStateOf(TextFieldValue("")) }

OutlinedTextField(
    value = field,
    onValueChange = { new ->
        val digits = new.text.filter { it.isDigit() }
        field = new.copy(
            text = digits,
            selection = TextRange(digits.length)      // курсор ставим осознанно
        )
    }
)
ПравилоВ состоянии — чистое значение, форматирование — через VisualTransformation. Текст правится программно — переходи на TextFieldValue или TextFieldState.

Кейс 3. Введенный адрес пропал

Форма доставки: город, улица, дом, комментарий курьеру.

Как пишут
var street by remember { mutableStateOf("") }
var house by remember { mutableStateOf("") }
var comment by remember { mutableStateOf("") }
Что видит пользователь
  • Заполнил адрес, свернул приложение — уточнить номер дома в переписке
  • Вернулся: все поля пустые
  • То же самое при повороте экрана и при смене темы в шторке настроек
Почему

remember живет столько же, сколько композиция. Поворот и пересоздание Activity обнуляют слоты. Разбор в статье про рекомпозицию, кейс 2.

Как надо
// короткая форма: значения переживут поворот и смерть процесса
var street by rememberSaveable { mutableStateOf("") }

Форма из нескольких полей с валидацией и отправкой — уже состояние экрана, его место во ViewModel:

@HiltViewModel
class DeliveryViewModel @Inject constructor(
    private val savedStateHandle: SavedStateHandle
) : ViewModel() {

    val street: StateFlow<String> = savedStateHandle.getStateFlow(key = STREET, initialValue = "")

    fun onStreetChange(value: String) {
        savedStateHandle[STREET] = value          // переживет и смерть процесса
    }

    private companion object { const val STREET = "street" }
}
ПравилоВсе, что ввел пользователь руками, — минимум rememberSaveable. Форма целиком — ViewModel с SavedStateHandle.

Кейс 4. Клавиатура закрывает поле

Экран отзыва: длинная форма, поле комментария внизу.

Как пишут
Scaffold(topBar = { TopAppBar(title = { Text(text = "Отзыв") }) }) { innerPadding ->
    Column(modifier = Modifier.padding(innerPadding)) {
        RatingStars(rating = state.rating, onRate = viewModel::onRate)
        OutlinedTextField(
            value = state.comment,
            onValueChange = viewModel::onCommentChange,
            modifier = Modifier.fillMaxWidth()
        )
        Button(onClick = viewModel::send) { Text(text = "Отправить") }
    }
}
Что видит пользователь
  • Нажал на поле комментария, открылась клавиатура
  • Поле и кнопка «Отправить» остались под клавиатурой — не видно, что печатаешь
  • Приходится закрывать клавиатуру, чтобы нажать кнопку
Почему

Клавиатура не входит в отступы Scaffold по умолчанию, а контент сам вверх не поднимается. Нужен imePadding — ровно один раз, иначе двойной отступ (разбор в статье про Scaffold, кейс 7).

Как надо
Scaffold(topBar = { … }) { innerPadding ->
    Column(
        modifier = Modifier
            .padding(innerPadding)
            .consumeWindowInsets(innerPadding)
            .imePadding()                              // единственное место
            .verticalScroll(rememberScrollState())     // форма должна прокручиваться
    ) { … }
}

Второй обязательный кусок — android:windowSoftInputMode="adjustResize" и enableEdgeToEdge() в Activity: без них система не сообщит Compose о клавиатуре.

ПравилоЭкран с полем ввода проверяется с открытой клавиатурой на коротком экране, а не только в эмуляторе с большим окном.

Кейс 5. Ошибка загорается на первой букве

Поле почты с проверкой формата.

Как пишут
var email by rememberSaveable { mutableStateOf("") }
val isEmailValid = email.matches(EMAIL_REGEX)

OutlinedTextField(
    value = email,
    onValueChange = { email = it },
    isError = !isEmailValid,                            // проверка на каждый символ
    supportingText = { if (!isEmailValid) Text(text = "Неверный формат почты") }
)
Что видит пользователь
  • Начал вводить почту
  • После первой же буквы поле стало красным и закричало об ошибке
  • Ошибка держится, пока адрес не дописан до конца — ощущение, что все делаешь не так
  • Высота поля скачет: подпись то появляется, то исчезает
Почему

Валидация выполняется на каждом изменении, хотя проверять незаконченный ввод бессмысленно. Правильный момент — потеря фокуса или попытка отправки.

Как надо
var email by rememberSaveable { mutableStateOf("") }
var wasFocused by rememberSaveable { mutableStateOf(false) }
var showError by rememberSaveable { mutableStateOf(false) }

OutlinedTextField(
    value = email,
    onValueChange = {
        email = it
        showError = false                   // начал править — ошибку убираем
    },
    isError = showError,
    supportingText = {
        Text(text = if (showError) "Неверный формат почты" else "Пришлем на нее чек")
    },
    modifier = Modifier.onFocusChanged { focusState ->
        if (focusState.isFocused) {
            wasFocused = true
        } else if (wasFocused) {
            showError = email.isNotEmpty() && !email.matches(EMAIL_REGEX)   // проверяем на выходе
        }
    }
)

Подпись занимает место всегда — поэтому высота поля не скачет: в supportingText либо подсказка, либо ошибка.

ПравилоВалидация — на потере фокуса и на отправке. На каждом символе снимается только уже показанная ошибка.

Кейс 6. Буквенная клавиатура для суммы

Перевод бонусов: поле суммы и поле телефона получателя.

Как пишут
OutlinedTextField(value = amount, onValueChange = { amount = it }, label = { Text("Сумма") })
OutlinedTextField(value = phone, onValueChange = { phone = it }, label = { Text("Телефон") })
Button(onClick = onSend) { Text(text = "Перевести") }
Что видит пользователь
  • Для суммы открывается обычная клавиатура — цифры приходится искать на втором слое
  • На кнопке действия «Ввод», который переносит строку вместо перехода к телефону
  • В сумму можно ввести буквы и запятую, запрос падает на сервере
Почему

KeyboardOptions не заданы, значит система показывает клавиатуру по умолчанию, а imeAction остается Default (раздел 04). Фильтрации ввода тоже нет.

Как надо
val focusManager = LocalFocusManager.current

OutlinedTextField(
    value = amount,
    onValueChange = { input -> amount = input.filter { it.isDigit() } },
    label = { Text(text = "Сумма") },
    singleLine = true,
    keyboardOptions = KeyboardOptions(
        keyboardType = KeyboardType.Number,
        imeAction = ImeAction.Next
    ),
    keyboardActions = KeyboardActions(
        onNext = { focusManager.moveFocus(FocusDirection.Down) }
    )
)

OutlinedTextField(
    value = phone,
    onValueChange = { phone = it },
    label = { Text(text = "Телефон") },
    singleLine = true,
    keyboardOptions = KeyboardOptions(
        keyboardType = KeyboardType.Phone,
        imeAction = ImeAction.Done
    ),
    keyboardActions = KeyboardActions(
        onDone = {
            focusManager.clearFocus()       // клавиатура закроется
            onSend()
        }
    )
)
ПравилоУ каждого поля осознанные keyboardType и imeAction. Последнее поле формы — Done с отправкой.

Кейс 7. Автофокус не срабатывает

Экран ввода кода из SMS: поле должно быть в фокусе сразу, клавиатура открыта.

Как пишут
@Composable
fun CodeScreen(viewModel: CodeViewModel = hiltViewModel()) {
    val focusRequester = remember { FocusRequester() }

    focusRequester.requestFocus()          // прямо в теле composable

    OutlinedTextField(
        value = state.code,
        onValueChange = viewModel::onCodeChange,
        modifier = Modifier.focusRequester(focusRequester)
    )
}
Что видит пользователь
  • Приложение падает с IllegalStateException: FocusRequester is not initialized
  • Либо не падает, но фокуса и клавиатуры нет — приходится тыкать в поле
Почему

В момент выполнения тела функции узел еще не в дереве: композиция только описывает, что показать, а применение идет позже (фазы кадра). Запрос фокуса — это действие, а действиям место в эффекте: сайд-эффекты, раздел 01.

Как надо
val focusRequester = remember { FocusRequester() }
val keyboard = LocalSoftwareKeyboardController.current

LaunchedEffect(Unit) {
    focusRequester.requestFocus()
    keyboard?.show()                       // на части устройств клавиатура сама не открывается
}

OutlinedTextField(
    value = state.code,
    onValueChange = viewModel::onCodeChange,
    modifier = Modifier.focusRequester(focusRequester),
    keyboardOptions = KeyboardOptions(
        keyboardType = KeyboardType.NumberPassword,
        imeAction = ImeAction.Done
    )
)
ПравилоrequestFocus() — только из LaunchedEffect, никогда из тела composable.

Кейс 8. Ввод отстает от печати

Поиск по каталогу услуг: список фильтруется по мере ввода.

Как пишут
@Composable
fun SearchScreen(viewModel: SearchViewModel = hiltViewModel()) {
    val state by viewModel.state.collectAsStateWithLifecycle()
    var query by remember { mutableStateOf("") }

    Column {
        CompanyHeader(company = state.company)              // перерисовывается на каждый символ
        OutlinedTextField(
            value = query,
            onValueChange = {
                query = it
                viewModel.search(it)                        // запрос на каждый символ
            }
        )
        ServicesList(services = state.services.filter { it.name.contains(query) })
    }
}
Что видит пользователь
  • Начал набирать «маник…»
  • Буквы появляются с задержкой, иногда проглатываются
  • Список моргает, на сервер уходит шесть запросов подряд
  • Результат показывает не то, что введено: отвечает самый медленный запрос
Почему

Две независимые причины. Первая — чтение query в теле экрана перезапускает весь экран на каждый символ (рекомпозиция, кейс 6 той статьи). Вторая — запрос уходит без задержки и без отмены предыдущего.

Как надо
@Composable
fun SearchScreen(viewModel: SearchViewModel = hiltViewModel()) {
    val state by viewModel.state.collectAsStateWithLifecycle()

    Column {
        CompanyHeader(company = state.company)
        SearchSection(onQueryChange = viewModel::onQueryChange)   // состояние уехало вниз
        ServicesList(services = state.services)
    }
}

@Composable
private fun SearchSection(onQueryChange: (String) -> Unit) {
    var query by rememberSaveable { mutableStateOf("") }

    OutlinedTextField(
        value = query,
        onValueChange = {
            query = it
            onQueryChange(it)
        },
        singleLine = true,
        modifier = Modifier.fillMaxWidth()
    )
}

SearchViewModel.kt — задержка и отмена лишних запросов

private val query = MutableStateFlow("")

fun onQueryChange(value: String) { query.value = value }

val state: StateFlow<SearchUiState> = query
    .debounce(300)                     // ждем паузу в наборе
    .distinctUntilChanged()
    .flatMapLatest { repository.search(query = it) }    // старый запрос отменяется
    .map(SearchUiState::map)
    .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), SearchUiState.EMPTY)
ПравилоПоле поиска — своя маленькая composable плюс debounce и flatMapLatest во ViewModel. Одного из двух всегда мало.

Кейс 9. Сервер вернул ошибку по полю, а пользователь ее ищет

Форма записи на услугу: имя, телефон, почта, комментарий. Часть проверок живет на сервере — формат телефона, занятая почта, черный список. Ответ приходит с указанием, какое именно поле не прошло.

Как пишут

BookingViewModel.kt

fun submit() {
    viewModelScope.launch {
        runCatching { repository.book(form = _state.value.form) }
            .onFailure { error ->
                ensureActive()
                _state.update { it.copy(errorMessage = error.messageOrDefault()) }   // просто текст
            }
    }
}

BookingScreen.kt

LaunchedEffect(state.errorMessage) {
    state.errorMessage?.let { snackbarHostState.showSnackbar(message = it) }
}
Что видит пользователь
  • Заполнил четыре поля, нажал «Записаться»
  • Снизу выехал снекбар «Неверный формат телефона» и через три секунды исчез
  • Какое поле править — приходится догадываться: ни одно не подсвечено
  • Телефон уже уехал вверх за экран, форма длинная — надо скроллить и искать
  • Повернул экран — снекбар выехал заново, хотя ничего не нажимал
Почему

Серверный ответ знает, какое поле виновато, но эта связь теряется на границе: во ViewModel она превращается в строку, а строка не умеет подсветить поле и уж тем более поставить в него фокус. Плюс ошибка хранится как обычное состояние и не гасится — отсюда повтор после поворота (та же ошибка, что в кейсе 6 статьи про сайд-эффекты).

Как надо

Три вещи: адресовать ошибку полю, дать каждому полю свой FocusRequester и провести фокус как разовое событие.

BookingUiState.kt — ошибка адресована полю

enum class BookingField { NAME, PHONE, EMAIL, COMMENT }

data class BookingUiState(
    val form: BookingForm = BookingForm(),
    val isSubmitting: Boolean = false,
    val fieldErrors: Map<BookingField, String> = emptyMap(),   // что показать под полем
    val focusTarget: BookingField? = null,                     // разовое событие: куда встать
    val message: String? = null                                // ошибка без привязки к полю
)

BookingViewModel.kt — маппинг ответа сервера в поля формы

fun submit() {
    if (_state.value.isSubmitting) return

    viewModelScope.launch {
        _state.update { it.copy(isSubmitting = true, fieldErrors = emptyMap()) }
        runCatching { repository.book(form = _state.value.form) }
            .onSuccess { … }
            .onFailure { error ->
                ensureActive()
                _state.update { it.copy(isSubmitting = false) }
                handleError(error = error)
            }
    }
}

private fun handleError(error: Throwable) {
    val validation = error as? ValidationException
    val errors = validation?.fields.orEmpty()
        .mapNotNull { (key, text) -> key.toBookingField()?.let { it to text } }
        .toMap()

    if (errors.isEmpty()) {
        _state.update { it.copy(message = error.messageOrDefault()) }   // поле неизвестно — общий текст
        return
    }

    _state.update {
        it.copy(
            fieldErrors = errors,
            focusTarget = FIELD_ORDER.first { field -> field in errors }  // первое сверху, не любое
        )
    }
}

fun onFocusHandled() {
    _state.update { it.copy(focusTarget = null) }     // событие погашено
}

private fun String.toBookingField(): BookingField? = when (this) {
    "name" -> BookingField.NAME
    "phone" -> BookingField.PHONE
    "email" -> BookingField.EMAIL
    "comment" -> BookingField.COMMENT
    else -> null                                      // сервер добавил новое поле — не падаем
}

private companion object {
    val FIELD_ORDER = listOf(
        BookingField.NAME, BookingField.PHONE, BookingField.EMAIL, BookingField.COMMENT
    )
}

BookingScreen.kt — реквестер на каждое поле

@Composable
fun BookingScreen(viewModel: BookingViewModel = hiltViewModel()) {
    val state by viewModel.state.collectAsStateWithLifecycle()
    val scrollState = rememberScrollState()

    // по реквестеру на поле: ключ — тот же enum, что и в ошибках
    val requesters = remember { BookingField.entries.associateWith { FocusRequester() } }

    LaunchedEffect(state.focusTarget) {
        val target = state.focusTarget ?: return@LaunchedEffect
        requesters[target]?.requestFocus()     // Column со scroll сам подкрутит поле в зону видимости
        viewModel.onFocusHandled()             // гасим событие: поворот не повторит прыжок
    }

    Column(
        modifier = Modifier
            .verticalScroll(scrollState)
            .imePadding()
    ) {
        BookingTextField(
            value = state.form.name,
            onValueChange = viewModel::onNameChange,
            label = "Имя",
            error = state.fieldErrors[BookingField.NAME],
            focusRequester = requesters.getValue(BookingField.NAME)
        )
        BookingTextField(
            value = state.form.phone,
            onValueChange = viewModel::onPhoneChange,
            label = "Телефон",
            error = state.fieldErrors[BookingField.PHONE],
            focusRequester = requesters.getValue(BookingField.PHONE),
            keyboardType = KeyboardType.Phone
        )
        …
    }
}

@Composable
private fun BookingTextField(
    value: String,
    onValueChange: (String) -> Unit,
    label: String,
    error: String?,
    focusRequester: FocusRequester,
    modifier: Modifier = Modifier,
    keyboardType: KeyboardType = KeyboardType.Text
) {
    OutlinedTextField(
        value = value,
        onValueChange = onValueChange,
        label = { Text(text = label) },
        isError = error != null,                    // рамка, подпись и label краснеют сами
        supportingText = { if (error != null) Text(text = error) },
        singleLine = true,
        keyboardOptions = KeyboardOptions(keyboardType = keyboardType, imeAction = ImeAction.Next),
        modifier = modifier
            .fillMaxWidth()
            .focusRequester(focusRequester)
    )
}

Что здесь сделано и зачем каждый кусок:

РешениеЧто оно закрывает
enum BookingField как ключ Связь «ответ сервера → поле формы» не теряется и проверяется компилятором. Строки "phone" живут в одном месте — в маппере
fieldErrors: Map Ошибка видна под своим полем, а не в исчезающем снекбаре. Сервер может вернуть несколько ошибок сразу — покажутся все
focusTarget отдельно от fieldErrors Подсветка — состояние, оно должно пережить поворот. Прыжок фокуса — событие, оно повторяться не должно
onFocusHandled() Гасит событие сразу после обработки
FIELD_ORDER.first { … } Если ошибок несколько, фокус встает в верхнюю по форме, а не в случайную из Map
verticalScroll у формы При установке фокуса прокручиваемый контейнер сам подводит поле в зону видимости
else -> null в маппере Сервер добавил поле, которого нет в приложении, — показываем общий текст вместо падения
Если форма в LazyColumn

Тогда поля за экраном не существуют в композиции, и requestFocus() у них вызвать некому. Порядок другой: сначала listState.animateScrollToItem(index) для нужного поля, и только потом запрос фокуса — на следующем кадре, когда элемент уже создан. Проще этого избежать: форма из четырех полей не нуждается в ленивом списке.

ПравилоОшибка от сервера адресуется полю, а не экрану. Подсветка — состояние, фокус — разовое событие с гашением.

Чеклист ревью

  1. Состояние поля под rememberSaveable, форма целиком — во ViewModel.
  2. В состоянии чистое значение, форматирование — VisualTransformation.
  3. Заданы keyboardType и imeAction, последнее поле отправляет форму.
  4. singleLine = true везде, где перенос строки не нужен.
  5. Валидация на потере фокуса, а не на каждом символе; место под подпись зарезервировано.
  6. requestFocus() — из LaunchedEffect.
  7. Экран проверен с открытой клавиатурой: поле и кнопка видны.
  8. Поиск: своя composable для поля плюс debounce и flatMapLatest.
  9. Ошибки от сервера привязаны к полям формы, а не показаны одним текстом; фокус встает в первое непрошедшее поле.
Итог

Поле ввода ничего не хранит: оно показывает переданное значение и сообщает о попытке ввода. Почти все ошибки — это либо разомкнутая петля «value → onValueChange → value», либо попытка поправить текст на лету без учета курсора, либо забытые настройки клавиатуры и фокуса, которые поле само не угадывает.
